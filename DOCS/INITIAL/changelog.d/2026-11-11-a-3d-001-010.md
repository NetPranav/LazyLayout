## 3D engine, Phases 3D-001 – 3D-010 (ROADMAP_3D.md)

- **3D-001 Stack:** decision 0013. three.js (WebGPU first, WebGL2 fallback) through the compositor; R3F and drei for the React export; three-mesh-bvh for raycasts; three-gpu-pathtracer in the editor only; Rapier for rigid bodies, loaded lazily; our own XPBD cloth. Every licence is in `LICENSES.md`. The physics benchmark is archived in `scripts/benchmarks/physics-3d.mjs`.
- **3D-002 GPU compositor:** decision 0011 (measured). One compositor owns every WebGL context. Small surfaces share one context and copy their result into their own canvas. 3D scenes get a context each, within a budget, and sleep with a poster when off screen. Lost contexts come back. The 2.5D surfaces now draw through it, and the browser never warns about too many contexts. `/editor/gpu-lab` and `tests/e2e/gpu-compositor.spec.ts`.
- **3D-003 Passes and the memory ledger:** every GPU texture, target and buffer is written in a ledger by owner and crossed out when freed (`src/core/gpu/ledger.ts`); render targets, ping-pong pairs and pass stacks with float targets only after a capability check (`passes.ts`). The surfaces use it; 50 mounting and unmounting return it to zero. A ledger view is on `/editor/gpu-lab`.
- **3D-004 GPU verification harness:** picture comparison in pure code (`src/core/gpu/compare.ts`: SSIM plus a neighbourhood error that forgives a 1 px shift but not a wrong colour or shape), a golden-image helper with an approve flow (`GOLDEN_UPDATE=1`) and a diff attached on failure (`tests/support/golden.ts`), and exact-time capture through the deterministic scheduler (`tests/e2e/gpu-harness.spec.ts`).
- **3D-005 Performance tiers:** three device tiers (phone, laptop, high end) with budgets for GPU time and memory, draw calls, triangles and simulation; every feature declares its cost and what it gives up first; `fitScene` says whether a scene fits and what to drop, in order (`src/core/gpu/tiers.ts`). A budget meter is on /design-system; the editor overlay comes with the first scene (3D-012).
- **3D-006 Worker job system:** one pool of workers runs heavy jobs off the main thread (`src/core/jobs`): priority, cancel (the worker is ended and replaced), results cached by key with a limit, an identical job in flight shared, progress, transferred buffers. The cloth simulation runs there; a ring shows its progress on the surface. A job cancelled and re-run in the same tick starts fresh (found by the browser test).
- **3D-007 Data blocks, schema v7:** the document gets optional shared tables for scenes, objects, meshes, materials, lights, cameras, armatures, actions, worlds and images (`src/core/document/scene3d.ts`); a `scene3d` layer points at a scene. Migration v6 to v7 is additive. "One material on many objects" with make-single-user, remove-unused, and large meshes as a binary (`meshBinary.ts`).
- **3D-008 Transforms and hierarchy:** pure 3D maths (`src/core/3d`): matrices and quaternions, all six Euler orders, world matrices through a parent chain with a parent-inverse and delta transforms, parenting and unparenting that keep the world position, apply transform and set origin (geometry, point, centre of mass).
- **3D-009 Units, axes and conventions:** Y-up, right-handed, metres and radians in the document, degrees in the UI; Z-up as a view option with exact inverses; a scene's pixels-per-metre and a default camera so a 2D frame turned 3D keeps its size on screen (within 0.5 px); glTF node and mesh mapping (`src/core/3d/units.ts`, `axes.ts`, `gltfMap.ts`).
- **3D-010 3D in the kernel:** tracks can target 3D data (`3d:objects/<id>/transform.location.x`, materials, lights, cameras, modifiers, shape keys); `evaluate3D()` resolves every animated 3D property and the world matrices at any time; Euler tracks become quaternions after interpolating; a parity diff compares two evaluated states. `evaluate()` for 2D is unchanged.
- **3D-013 The editable mesh:** a BMesh-style mesh (vertices, edges, n-gon faces, loops, attributes), triangulation for drawing, and dirty-range bookkeeping so editing one vertex uploads one vertex (`src/core/3d/mesh/`).
- **3D-014 and 3D-015 Navigation and selection:** orbit, pan, dolly, fly, front/back/left/right/top/bottom views, frame selected, gestures for mouse, trackpad and touch (`src/core/3d/camera/`); picking by ray with three-mesh-bvh, click, box and lasso selection, select linked and similar (`src/core/3d/pick/`).
- **3D-016 and 3D-017 Moving and snapping:** a modal G / R / S session with axis locks and typed values, gizmo handles with hit testing and drag, one undo step per gesture (`src/core/3d/transform/`); snapping to increment, grid, vertex, edge and face, pivots, transform orientations and the 3D cursor (`src/core/3d/snap/`).
- **3D-020 Keymaps:** a Blender keymap (G R S, Tab, numpad views, Shift+A, X, H) and a Beginner keymap with a toolbar button for everything; a conflict test proves no two commands share a key in the same context (`src/core/3d/keymap/`).
- **3D-011 3D commands and Adjust last operation:** every 3D edit is a typed command with one undo step (add primitives, lights, camera, delete, duplicate, parent, apply transform, set origin, join, materials); after "Add Cylinder" a small panel changes its vertex count as the same undo step. The agent bridge lists them all. A text field that disappears while focused no longer leaves Undo and shortcuts switched off.
- **3D-012, 3D-018, 3D-019 The 3D scene on the canvas:** Insert > 3D scene puts a scene box on the page (drawn through the compositor, asleep with a poster off screen, recovering from context loss); double-click enters 3D editing, Escape leaves. Wireframe, Solid, Material preview and Rendered shading with X-ray; overlays (grid, axes, origins, normals, face orientation, statistics) and the 3D cursor. The viewport works at any stage zoom.
- **3D-027 and 3D-028 Path engine and distance fields:** flatten curves to a tolerance, offset with round, mitre and bevel joins, booleans and holes on rings (`src/core/3d/path/`), and an exact signed distance field with the height profile for inflating (`src/core/3d/sdf/`); rings with repeated joints are cleaned first.
- **3D-025 Primitives with parameters and handles:** cube, cylinder, cone, UV sphere, ico sphere, torus, plane, circle, capsule and rounded box, each with editable parameters and drag handles; the mesh keeps its recipe, so changing a parameter rebuilds it as one undo step (`src/core/3d/primitives/`).
- **3D-030 Modifier stack:** an ordered, non-destructive stack per object (mirror, array, solidify, transform, displace) with viewport and render toggles, apply, a cache by input and worker evaluation for heavy stacks; parameters can be keyframed and are evaluated by the kernel (`src/core/3d/modifiers/`).
- **3D-021 and 3D-024 Outliner and shared data blocks:** the scene tree (collections, objects, data, materials, modifiers) with visible, selectable and render toggles, reparenting that keeps the world transform; user counts for shared blocks, "Make single user", and copy and paste attributes (`src/core/3d/outliner/`, `src/core/3d/blocks/`).
- **3D-029 and 3D-026 Make 3D and 3D text:** turn a 2D layer into extruded, inflated, lathed or flat 3D, linked to its source (`src/core/3d/make3d/`); 3D text from the font outlines (opentype.js 2.0.0, new dependency) with extrude depth, bevel, alignment and spacing, and convert to mesh (`src/core/3d/text/`).
- **3D-022 and 3D-023 Properties editor and Looks:** the right panel's 3D side becomes the Properties editor with Object, Modifiers, Physics, Material, Object data, Constraints, World and Render tabs and a Simple and a Pro face; looks are named sets of values sized to the object (built in and saved from any object) with a thumbnail strip (`src/editor/panels/details/properties3d/`, `src/core/3d/looks/`).
