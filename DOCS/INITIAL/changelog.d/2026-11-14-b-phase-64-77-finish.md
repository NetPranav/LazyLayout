### Phases 64 to 77: CI failures fixed, and the Phase 74, 75 and 77 controls in the new editor

The Lane B specs that were red on `main` now pass in Chromium and Firefox, and three engine phases that could only be reached by command have their controls in the Design inspector.

#### Added
- **Compositing section** in the inspector (Phase 74): Isolate group, Adjust what is behind (eight filters, and Make an adjustment layer), Mask (mode, shape, position, size, radius, feather, expand, opacity, path, fill) and Matte (source layer, mode, show the source). Each control calls `layer.setBlend`, `layer.setAdjustment`, `layer.setMask` or `layer.setMatte`.
- **Effect stack section** in the inspector (Phase 75): add one of the six effects, edit its settings, move it up or down, switch it off, remove it; each effect shows the route the rules chose (CSS or SVG) and the reason. Motion blur with a shutter angle.
- **Bake** on each expression in the Parent & links section (Phase 77): `layer.bakeExpression`, one undo step.
- `measureAtRest` (`src/core/engine/stage/StageEngine.ts`) and `KernelAdapter.atRest`: run a measurement with the animation taken off the layers, then put it back.
- `tests/e2e/wire-74-77-inspector.spec.ts` (three tests), and a unit test for `atRest`.

#### Fixed
- **A layer half way through a move could not be clicked (Phase 69).** In Motion with the playhead off 0, any re-render re-measured the layer's click box with the move in it and then moved it again, so the click selected the frame behind. The stage now measures at rest. This was the Firefox and WebKit failure of "the selected animated layer shows its motion path".
- **Scrubbing 200 animated layers took 91 ms a frame (Phase 64).** A seek re-rendered the canvas (the Artboard subscribed to the playhead), re-rendered the timeline (a new work-area object on every seek), and made the browser restyle every element (the playhead's label replaced its text node, which re-matches the page-wide `html:has(…) *` rules). About 25 ms now, in headless Chromium.
- **The graph editor said "Select an animated layer" with a keyframe selected (Phase 67)** when the layer selected on the canvas was a different one. It follows the selected keyframe first.
- `tests/e2e/compositing.spec.ts`: the adjustment's pixel check runs only where a screenshot can show a backdrop blur (Playwright's Firefox and WebKit never draw one); the computed filter is compared in every browser.

#### Not done
- Stopwatches on the timeline's property rows for `adjust.*`, `mask.*` and `fx.*`; an expression field on the timeline rows.
- WebKit could not be run on the development machine; CI is the check for it.
- The `html:has(.ll-editor-root) *` rules in `src/editor/styles/globals.css` still make any DOM insertion restyle the page; only the per-frame caller was changed. Raised with Lane A in discussion 98.
