## Decisions made
- **Front-most first order (`buildLayerTree.ts`)**: Followed Figma and LazyLayout conventions where internal back-to-front storage order (`children[0]` is back, `children[N-1]` is front) is inverted when constructing `LayerItem[]` so front-most layers appear on top.
- **Bi-directional selection and frame synchronization (`useLeftPanelData.ts`)**: When selecting any layer in the tree (single, Shift-range, or Ctrl-toggle), `useCanvasViewStore.setActiveFrame` is immediately synced to the enclosing frame ID, ensuring consistent frame focus across inspector and canvas tools.
- **External selection auto-expansion (`useLeftPanelData.ts`)**: Added an ancestor-revealing effect matching `ancestorsOf(layers, activeId)` so selections made directly on the canvas or from inspector controls automatically expand all parent containers in the Layers tree.
- **Page CRUD fallback resilience (`usePagesData.ts`)**: Supported both After-track dynamic actions (`addPage`, `updatePage`, `deletePage`, `duplicatePage`) and pristine core store fallbacks so page switching and creation work reliably in both Initial and Full edition runtimes.
- **Header slot mode sensitivity (`LeftPanelConnected.tsx`)**: `LeftPanelConnected` automatically inserts `<PageSwitcher {...pagesData} />` into the `headerStart` slot when in `design` mode, while cleanly yielding to section titles ("Layers" or "Files") in `motion` and `code` modes.
