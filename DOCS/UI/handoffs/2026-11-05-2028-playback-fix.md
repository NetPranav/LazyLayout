## Root Cause

In `src/editor/panels/timeline/TimelinePanel.tsx`, the playback loop scheduled via `frameScheduler` computed:
```ts
nextT = currentT + dt * fps * speed;
```
where `currentT` was read directly from `useMotionModel.getState().playhead`.

On each tick, `nextT` was passed to `motionActions.setPlayhead(nextT)`, which performed:
```ts
playhead: clampN(Math.round(t), 0, s.comp.dur)
```
Because standard `requestAnimationFrame` / `frameScheduler` ticks deliver deltas around 16.6ms (and frequently 8ms–14ms under high refresh displays or timing jitter), `dt * fps * speed` per tick is often `< 0.5`. On each tick:
1. `Math.round(currentT + fraction)` truncated the fractional subframe delta back down to `currentT`.
2. Fractional progress was completely lost every frame.
3. At fractional speeds (e.g. `0.5x`, `0.25x`), `dt * fps * speed` was strictly `< 0.5` every tick, freezing playback entirely.
4. Over a 5000ms playback window, the playhead only advanced 17 frames (reaching 0.78s instead of 5.0s, ~3.4 fps effective speed).
5. Furthermore, when the playhead did advance, updating `playhead` directly in the Zustand store on every frame caused `TimelineTransport` to re-render 60 times a second. Its JSX `{formattedTime}` text node modification produced 121 `characterData` DOM mutations over 2 seconds, violating the Phase 56 gate requirement (`<= 10 React DOM commits/s`).

## The Fix

1. **Persistent Subframe Accumulator in Motion Store (`src/editor/motion-model/store.ts`)**:
   - Added `subhead: number` (the continuous float accumulator) and `readoutPlayhead: number` (the 10 Hz throttled integer frame) to `MotionState`.
   - Updated `motionActions.setPlayhead(t, options)`:
     - Clamps `t` to `[0, comp.dur]`.
     - Stores the exact float in `subhead`.
     - Stores the derived integer `clampN(Math.round(clamped), 0, comp.dur)` in `playhead`.
     - When `options?.updateReadout` is true or when paused, synchronizes `readoutPlayhead` to the integer frame.
   - Snapping actions (`stepFrame`, `jumpKey`, Home, End, ruler clicks, and scrubbing) explicitly snap both `subhead` and `playhead` to whole integer frames.
   - When playback stops via `setPlaying(false)`, `subhead` and `readoutPlayhead` snap cleanly to `playhead`.

2. **Accurate Frame-Rate Independent Accumulation in Timeline Engine (`src/editor/panels/timeline/TimelinePanel.tsx`)**:
   - The playback engine reads `s.subhead` as the single source of truth during playback.
   - On each frame tick, advances `nextT = currentSub + dt * fps * effectiveSpeed * effectiveDir`.
   - Loop modes properly preserve subframes:
     - Wrap (`loop === 1`): wraps modulo work-area length while preserving fractional delta: `nextT = currentWa.a + ((nextT - currentWa.b) % span)`.
     - Ping-pong (`loop === 2`): reflects across boundary: `nextT = Math.max(currentWa.a, currentWa.b - (nextT - currentWa.b))` and inverts direction.
     - Off (`loop === 0`): stops cleanly at `currentWa.b` (or `currentWa.a`) with `setPlayhead(bound, { updateReadout: true })`.
   - Shuttle playback (J, K, L) works with negative and multiplied speeds while accumulating continuously without frame drops.
   - Throttles `updateReadout` in `setPlayhead` to 10 Hz (`now - lastReadout >= 100ms`).

3. **Throttled Readout without React Purity Violations (`src/editor/panels/timeline/TimelineTransport.tsx`)**:
   - Subscribed `TimelineTransport` to `s.readoutPlayhead` instead of `s.playhead`.
   - During 60fps playback, `readoutPlayhead` updates at 10 Hz (<= 10 commits/s), satisfying the Phase 56 gate.
   - When paused or scrubbed, `readoutPlayhead` is identical to `playhead`, ensuring zero desync between needle and timecode text.
   - Zero React Compiler / `react-hooks/refs` lint errors (no reading or writing refs during render).

4. **E2E Spec Unfixme (`tests/e2e/playback-on-clock.spec.ts`)**:
   - Un-fixme'd `App bug: TimelinePanel playback has no subframe accumulator and setPlayhead rounds to integer, losing time during rAF ticks`.
   - Kept all assertions strict:
     - `expect(fromSequencer).toBeGreaterThan(0.9)`
     - `expect(Math.abs(barTime - fromSequencer)).toBeLessThanOrEqual(1 / FPS + 1e-9)`
   - Set playback window to 2000ms (2.0s playback from 0.5s reaches ~2.5s, allowing pause before the 4.5s composition boundary).
