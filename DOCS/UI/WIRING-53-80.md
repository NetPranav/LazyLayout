# Wiring Plan: Phases 53–80 (Motion Engine into the New Editor)

This document maps Stage 2 (Phases 53–80) of LazyLayout from the engine implementation (`src/core`) to the new editor UI (`src/editor`, served at `/editor`). It tracks what each phase promises, where its engine code lives, its current reachability in the new editor, and the wiring required to make it functional.

| Phase | What the roadmap promises the user can do | Where the engine code is | Reaches new editor today? | Missing wiring |
|---|---|---|---|---|
| **53 · Animation grammar: close schema gaps** | Lossless schema representation for Exit, Focus, Stagger, LayoutTransition clips; lossless `pointerMove`, `drag`, `time` triggers. Menus offer Exit, Focus, and Layout categories. | `src/core/document/motion.ts`, `migrations/v5-to-v6.ts`, `src/core/kernel/evaluate.ts`, `src/core/animation/clip-adapter.ts` | **Partly** (`src/editor/motion-model/sync.ts`, `src/editor/panels/inspectors/LayerInspector.tsx`) | Two-way binding for all 10 `CLIP_TYPES` and 12 `TRIGGERS` in `LayerInspector.tsx` and `sync.ts`; writing `{ type, trigger }` to document clips via `documentCommands.updateClip` / `addClip`. |
| **54 · Transport & one clock** | Transport bar (play, pause, timecode, loop, fps, shuttle J/K/L) controls the entire studio via a shared store outside React. Frame stepping at 24/30/60 fps. | `src/core/time/transport.ts`, `src/core/time/useTransportTime.ts` | **Yes** (`src/editor/motion-model/store.ts`, `src/editor/panels/timeline/TimelineTransport.tsx`, `src/editor/panels/timeline/TimelinePanel.tsx`, `src/editor/shell/EditorShell.tsx`) | Proved by `src/editor/motion-model/__tests__/oneClock.test.ts` and `tests/e2e/wire-54-transport.spec.ts`. Transport is the one clock; motion model mirrors `transportStore`; `transportCommands` and `transportDriver` registered in shell; UI controls route to `transport.*`. |
| **55 · Frame scheduler** | One `requestAnimationFrame` loop with ordered execution phases (input → evaluate → apply → render → overlay → stats); deterministic mode for test clock and export queue. | `src/core/time/scheduler.ts` | **Yes** (`src/editor/motion-model/store.ts`, `src/editor/stage/Artboard.tsx`, `src/editor/stage/ValueHud.tsx`, `src/editor/stage/MotionPathOverlay.tsx`, `src/editor/stage/OnionSkinOverlay.tsx`, `src/editor/panels/timeline/TimelinePlayhead.tsx`) | Proved by `src/editor/motion-model/__tests__/schedulerPhases.test.ts` and `tests/e2e/wire-55-scheduler.spec.ts`. During playback, transport advances in `evaluate`, Motion store playhead updates in `apply`, stage canvas renders in `render`, and overlays (ValueHud, MotionPathOverlay, OnionSkinOverlay, playhead) update in lockstep in `overlay`. Paused seeking/stepping applies immediately. `window.__LL_SCHEDULER__` test seam enables deterministic virtual stepping. |

| **74 · Blend modes, adjustment layers, masks & mattes** | Per-layer CSS blend modes, isolated groups, backdrop-filter adjustment layers, SVG alpha/luma masks (rect, ellipse, path; the path morphs) and track mattes (another layer is the mask). | `src/core/render/compositing.ts`, `src/core/geometry/matteShape.ts`, `src/core/kernel/evaluate.ts` (`withMatte`), `src/core/render/geometry.ts`, `src/core/engine/stage/styleWrites.ts` | **Drawn: yes** (the engine-drawn stage shows blend, isolation, adjustment, masks and mattes the moment the properties are set; checked 2026-11-12). **Controls: no.** | The Blend mode control exists (writes `appearance.blendMode`, which now draws). Missing controls, each a command already (Law 20), so the inspector only calls them: **Isolate group** → `layer.setBlend {isolate}`; **Adjustment** (a layer type, plus Blur, Brightness, Contrast, Saturation, Hue, Grayscale, Sepia, Invert) → `layer.setAdjustment {asLayer, blur, brightness, contrast, saturate, hueRotate, grayscale, sepia, invert}`; **Mask** (Mode: none / alpha / alpha inverted / luma / luma inverted; Shape: rectangle / ellipse / path; X, Y, W, H (−1 = the layer's own), Radius, Feather, Expansion, Fill, Opacity) → `layer.setMask`; **Matte** (pick-whip or menu to choose a source layer, Mode, Show source) → `layer.setMatte {sourceId, mode, showSource}`. All of them are keyframeable except the modes: the numbers, `mask.path` and `mask.fill` are paths for the timeline's stopwatches (`adjust.*`, `mask.*`). A track matte is drawn only when its source is a box on the same absolute canvas (see `matteShape.ts`); a layer under a flow layout gives no matte. Phase 73's pick-whip is the natural control for choosing the source. |
| **75 · Effect stack & motion blur** | Keyframeable effect list (blur, glow, drop shadow, colour adjust, displacement, noise), each with a visible route and reason; opt-in motion blur from velocity. | `src/core/render/fxStack.ts`, `src/core/rules/effectRouting.ts`, `src/core/engine/stage/fxFilters.ts`, `src/core/kernel/evaluate.ts` (`withMotionBlur`) | **Drawn: yes** (stage lab and the engine-drawn canvas). **Controls: no.** | An **Effects** section in the inspector: a list of up to 8 effects, **Add effect** (menu of the six types) → `layer.addEffect {type}`; per effect: enable switch → `layer.setEffect {slot, enabled}`; its parameters (blur: Radius; glow: Radius, Intensity, Colour, Opacity; drop shadow: X, Y, Radius, Colour, Opacity; colour adjust: Brightness, Contrast, Saturation, Hue; displacement: Scale, Frequency, Seed; noise: Amount, Size, Seed) → `layer.setEffect {slot, params}` (each also gets a stopwatch: the path is `fx.<slot>.<param>`); reorder by drag → `layer.moveEffect {slot, to}`; remove → `layer.removeEffect {slot}`; beside each effect its route: `routeEffect(type)` gives `{backend, reason}` (show the reason as help text). **Motion blur**: the timeline's existing switch → `layer.setMotionBlur {on}` plus a **Shutter angle** field → `layer.setMotionBlur {shutterAngle}`. |
