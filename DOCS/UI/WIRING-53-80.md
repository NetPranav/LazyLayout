# Wiring Plan: Phases 53–80 (Motion Engine into the New Editor)

This document maps Stage 2 (Phases 53–80) of LazyLayout from the engine implementation (`src/core`) to the new editor UI (`src/editor`, served at `/editor`). It tracks what each phase promises, where its engine code lives, its current reachability in the new editor, and the wiring required to make it functional.

| Phase | What the roadmap promises the user can do | Where the engine code is | Reaches new editor today? | Missing wiring |
|---|---|---|---|---|
| **53 · Animation grammar: close schema gaps** | Lossless schema representation for Exit, Focus, Stagger, LayoutTransition clips; lossless `pointerMove`, `drag`, `time` triggers. Menus offer Exit, Focus, and Layout categories. | `src/core/document/motion.ts`, `migrations/v5-to-v6.ts`, `src/core/kernel/evaluate.ts`, `src/core/animation/clip-adapter.ts` | **Partly** (`src/editor/motion-model/sync.ts`, `src/editor/panels/inspectors/LayerInspector.tsx`) | Two-way binding for all 10 `CLIP_TYPES` and 12 `TRIGGERS` in `LayerInspector.tsx` and `sync.ts`; writing `{ type, trigger }` to document clips via `documentCommands.updateClip` / `addClip`. |
| **54 · Transport & one clock** | Transport bar (play, pause, timecode, loop, fps, shuttle J/K/L) controls the entire studio via a shared store outside React. Frame stepping at 24/30/60 fps. | `src/core/time/transport.ts`, `src/core/time/useTransportTime.ts` | **Yes** (`src/editor/motion-model/store.ts`, `src/editor/panels/timeline/TimelineTransport.tsx`, `src/editor/panels/timeline/TimelinePanel.tsx`, `src/editor/shell/EditorShell.tsx`) | Proved by `src/editor/motion-model/__tests__/oneClock.test.ts` and `tests/e2e/wire-54-transport.spec.ts`. | **55 · Frame scheduler** | One `requestAnimationFrame` loop with ordered execution phases (input → evaluate → apply → render → overlay → stats); deterministic mode for test clock and export queue. | `src/core/time/scheduler.ts` | **Yes** (`src/editor/motion-model/store.ts`, `src/editor/stage/Artboard.tsx`, `src/editor/stage/ValueHud.tsx`, `src/editor/stage/MotionPathOverlay.tsx`, `src/editor/stage/OnionSkinOverlay.tsx`, `src/editor/panels/timeline/TimelinePlayhead.tsx`) | Proved by `src/editor/motion-model/__tests__/schedulerPhases.test.ts` and `tests/e2e/wire-55-scheduler.spec.ts`. | **74 · Blend modes, adjustment layers, masks & mattes** | Per-layer CSS blend modes, isolated groups, backdrop-filter adjustment layers, SVG alpha/luma masks (rect, ellipse, path; the path morphs) and track mattes (another layer is the mask). | `src/core/render/compositing.ts`, `src/core/geometry/matteShape.ts`, `src/core/kernel/evaluate.ts` (`withMatte`), `src/core/render/geometry.ts`, `src/core/engine/stage/styleWrites.ts` | **Drawn: yes** (the engine-drawn stage shows blend, isolation, adjustment, masks and mattes the moment the properties are set; checked 2026-11-12). **Controls: no.** | The Blend mode control exists (writes `appearance.blendMode`, which now draws). Missing controls, each a command already (Law 20), so the inspector only calls them: **Isolate group** → `layer.setBlend {isolate}`; **Adjustment** (a layer type, plus Blur, Brightness, Contrast, Saturation, Hue, Grayscale, Sepia, Invert) → `layer.setAdjustment {asLayer, blur, brightness, contrast, saturate, hueRotate, grayscale, sepia, invert}`; **Mask** (Mode: none / alpha / alpha inverted / luma / luma inverted; Shape: rectangle / ellipse / path; X, Y, W, H (−1 = the layer's own), Radius, Feather, Expansion, Fill, Opacity) → `layer.setMask`; **Matte** (pick-whip or menu to choose a source layer, Mode, Show source) → `layer.setMatte {sourceId, mode, showSource}`. All of them are keyframeable except the modes: the numbers, `mask.path` and `mask.fill` are paths for the timeline's stopwatches (`adjust.*`, `mask.*`). A track matte is drawn only when its source is a box on the same absolute canvas (see `matteShape.ts`); a layer under a flow layout gives no matte. Phase 73's pick-whip is the natural control for choosing the source. |
| **75 · Effect stack & motion blur** | Keyframeable effect list (blur, glow, drop shadow, colour adjust, displacement, noise), each with a visible route and reason; opt-in motion blur from velocity. | `src/core/render/fxStack.ts`, `src/core/rules/effectRouting.ts`, `src/core/engine/stage/fxFilters.ts`, `src/core/kernel/evaluate.ts` (`withMotionBlur`) | **Drawn: yes** (stage lab and the engine-drawn canvas). **Controls: no.** | An **Effects** section in the inspector: a list of up to 8 effects, **Add effect** (menu of the six types) → `layer.addEffect {type}`; per effect: enable switch → `layer.setEffect {slot, enabled}`; its parameters (blur: Radius; glow: Radius, Intensity, Colour, Opacity; drop shadow: X, Y, Radius, Colour, Opacity; colour adjust: Brightness, Contrast, Saturation, Hue; displacement: Scale, Frequency, Seed; noise: Amount, Size, Seed) → `layer.setEffect {slot, params}` (each also gets a stopwatch: the path is `fx.<slot>.<param>`); reorder by drag → `layer.moveEffect {slot, to}`; remove → `layer.removeEffect {slot}`; beside each effect its route: `routeEffect(type)` gives `{backend, reason}` (show the reason as help text). **Motion blur**: the timeline's existing switch → `layer.setMotionBlur {on}` plus a **Shutter angle** field → `layer.setMotionBlur {shutterAngle}`. |
| **76 · Property links & pick-whip** | Link one layer's property to another's (rotation to position) with a range or curve map; drag a pick-whip from a property to another; cycles are refused with their chain. | `src/core/links/linkModel.ts`, `src/core/links/linkCommands.ts`, `src/core/kernel/evaluate.ts` (`applyLinks`) | **Drawn: yes** (the stage follows a link the moment it is set; stage lab "Load link scene"). **Controls: no.** | **Pick-whip:** a whip handle beside every numeric property in the inspector and in the timeline's property rows; dragging it to another numeric property (of any layer, or the same one) calls `layer.setLink {id, targetProperty, sourceLayerId, sourceProperty}` (the drag goes from the driven property to the one it reads, as in After Effects). Show the outcome: on success `description` ("Hero.transform.rotate ← Null.transform.x"); on failure `message`, and for `code: "LINK_CYCLE"` highlight the `chain` (a list of `{layerId, property}`) in the UI. A **Links** list per layer: read `readLinks(layer.properties)` (slot, target, source, sourceProperty, map, enabled); an enable switch → `layer.setLink {slot, ..., enabled}`; **Map** (Direct / Range / Curve) with In min, In max, Out min, Out max, Clamp and an easing picker → `layer.setLink` with `map`, `inMin`, `inMax`, `outMin`, `outMax`, `clamp`, `curve`; remove → `layer.removeLink {slot}`. A linked property's own field should show as driven (greyed with the source named) since the link overrides it. The map numbers are animatable paths (`link.<slot>.inMin` etc.). |
| **77 · Expressions** | Type an expression on a property (`wiggle(2, 10)`); see errors where they are; bake to keyframes. | `src/core/expressions/` (`parse.ts`, `evaluate.ts`, `expressionCommands.ts`), `src/core/kernel/evaluate.ts` (`drivenValue`) | **Drawn: yes** (stage lab "Load expression scene"). **Controls: no.** | **Expression field:** beside every numeric property in the inspector and the timeline rows, an **Expression** toggle (the stopwatch with Alt held, as in After Effects) that opens a one-line code field. On commit call `layer.setExpression {id, property, text}`; on `ok: false` show `message` and, for `EXPR_SYNTAX` / `EXPR_TYPE` / `EXPR_LIMIT`, underline the character in `errors[0].at` (0-based); for `LINK_CYCLE` highlight the `chain`. A property with an expression shows as driven (its value field greyed, the expression's text named). Read the layer's expressions with `readExpressions(layer.properties)` (slot, target, text, enabled): an enable switch → `layer.setExpression {slot, ..., enabled}`; remove → `layer.removeExpression {id, property}`; **Convert to keyframes** → `layer.bakeExpression {id, property}` (refuses with `TOO_LONG` over 2400 frames: say "narrow the work area"). |
