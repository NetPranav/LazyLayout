# Task: dark theme first, with semantic tokens

**User direction:** the colors built so far are the **light** theme only. Build a **dark** theme first (the primary one) from Figma's dark UI, then design the rest in dark. Read `DOCS/UI/PALETTE.md` (rewritten, it is the source of truth) and look at `DOCS/UI/palette-refs/ref-02-figma-dark.png`. No accent color. Do not touch the imported components in `src/editor/components/imported/` (user: as-is).

## Do
1. **Semantic tokens.** In `src/editor/styles/tokens.css`, replace the numbered colors (`--ll-neutral-*`) with the semantic tokens in `PALETTE.md`: `--ll-surface-backdrop`, `-canvas`, `-panel`, `-bar`, `-raised`, `--ll-border-color`, `--ll-text-primary`, `-secondary`, `-muted`, `--ll-control-primary-bg`, `-fg`. Dark values are the default on `:root`. Light values apply under `:root[data-theme="light"]`. Dark also applies under `[data-theme="dark"]`.
2. **Tailwind.** In `tailwind.css`, expose them as colors: `ll:bg-surface-canvas`, `ll:bg-surface-panel`, `ll:bg-surface-bar`, `ll:bg-surface-raised`, `ll:bg-surface-backdrop`, `ll:text-primary`, `ll:text-secondary`, `ll:text-muted`, `ll:bg-control-primary`, `ll:text-control-primary-fg`, `ll:border-border`. Remove the numbered neutral colors. The shadow color token must also differ per theme (a stronger black alpha in dark).
3. **Refactor everything built so far** to the semantic classes, with no visual regression in light: `Button`, `SegmentedControl`, `Tooltip`, `TopBar`, `Swatch`, `WorkspaceFrame`, `EditorShell`, `DesignSystemPage` (not `imported/`). Map: old `neutral-400` is backdrop, `-100` is canvas, `-200` is panel, `-50` is bar, `-0` is raised, `-800` is text-secondary, `-1000` is text-primary on surfaces and `control-primary-bg` for primary controls. Focus ring uses `text-primary`. Hover and active states use `surface-bar` on panels and `surface-panel` on raised, so they stay visible in both themes.
4. **Theme switch.** `layout.tsx` sets `data-theme="dark"` on `<html>` by default. Add a small `ThemeToggle` component (a ghost icon button with sun and moon from `lucide-react`, tooltip "Switch theme") in `src/editor/components/`, shown on the design system page in the right panel header and in the top bar's right group before Settings. It sets `data-theme` and stores the choice in `localStorage`, read before first paint without a flash (an inline script in `layout.tsx` is allowed for this). Respect `prefers-color-scheme` only when nothing is stored? No: default is dark when nothing is stored.
5. **Design system page.** Colors page shows both themes: a dark column and a light column for each role, with token name and both hex values, and the workspace preview in the current theme. Add the Figma-derived dark roles with their sample text, plus a contrast ratio line for primary and secondary text on each surface. Type, Spacing, Radii, Shadows pages must read correctly in both themes.
6. **Dark first.** Check `/editor` and `/design-system` in dark first, then light. Fix anything unreadable, for example black icons on dark or invisible hairlines.
7. Docs: `INTEGRATION.md` (token rename), `DECISIONS.md` for any choice you make, handoff.
