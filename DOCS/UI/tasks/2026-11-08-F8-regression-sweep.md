## Part 1: the known breakage (fix first)
1. **Context menus must NOT use retarget/travel.** In P (grep `ctxmenu`, `contextmenu`, `openCtx`, `closeCtx`, `.ctx`, `#cmenu`, canvas, element, layer, timeline menus) a context menu opens at the pointer with its own pop-in (origin at the pointer, spring, rows stagger) and a second right-click (anywhere, even while open) closes the old one immediately and opens a new one at the new pointer position with a fresh pop-in; never a slide between positions. Right-click on a different target (canvas vs element vs layer row vs timeline clip) swaps the menu content, not a glide. Rapid repeated right-clicks, right-click while the open animation is running, right-click then Esc, scroll/resize/blur closes, clicking an item closes it: all must work with no stuck, doubled, or half-open menu, no wrong position, no leaked listeners. Menus clamp inside the viewport (flip left/up) like P. Restrict F6's retarget helper to the families P actually retargets (top-bar menus hover swap, option popovers, pickers, toolbar popovers); keep context menus on the open-fresh path. Files: `src/editor/components/ContextMenu.tsx`, `Popover.tsx`/`Menu.tsx` retarget code, `shell/canvas-chrome/CanvasContextMenu.tsx`, `shell/left-panel/LayerContextMenu.tsx`, `panels/timeline/TimelineMenus.tsx`, stage right-click handlers.
2. **Cursor transition with menus.** The canvas custom cursor (`ll-cursors` block in P, `#ll-cur`) hides while a context menu is open and comes back with its crossfade when the menu closes and the pointer is over the canvas; over the menu itself and all panels the system cursor shows; cursor kind changes (move, resize, rotate, hand, crosshair, I-beam, eyedropper, zoom, locked) must crossfade with blur and rotate on springs exactly as P, with no stuck hidden cursor after a menu closes (also after Esc, after item click, after right-click-drag, after window blur) and no double cursor.
