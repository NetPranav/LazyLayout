# Task F5: no raw browser buttons or selects anywhere in the editor; use our own components

Read `DOCS/UI/tasks/2026-11-08-COMMON.md` first. User feedback (2026-11-08), screenshot `DOCS/UI/handoffs/screenshots/user/2026-11-08-colour-picker-feedback-2.png` (LOOK AT IT FIRST): in the colour picker the Solid/Linear/Radial/Conic/Image tabs are raised, bordered, grey **native browser buttons**, the Hex dropdown and the inspector "Font / Scale / Shadow" selects look native too. The user wants every such button to use the **top-centre button style** = the top-bar mode switch (`src/editor/components/ModeTabs.tsx` and `SegmentedControl.tsx`: 32px (24px in compact popovers), 2px padding, 500 weight, muted text when unselected, one sliding `--ll-select-bg` tile, no borders, radius 6). Root cause: there is no CSS reset (no Preflight) so any native `<button>`/`<select>`/`<input>` that is not fully styled shows the browser default (raised border, ButtonFace background).

## Do

Prioritise: ColorPicker (mode tabs, Hex/RGB/HSL/OKLCH select, eyedropper, add-swatch, swatches), FontPicker (category tabs, rows, footer buttons), FramePresetsPanel, OptionsPopover, all inspector sections and the "more options" popovers (`panels/details/**`, `shell/right-panel/**`), layers search/page selector, timeline, canvas chrome, code/console panels, top bar. Verify in the browser too: headless Playwright over `/editor` (Design, Motion, Code; open the colour picker, font picker, frame presets, every section's sliders popover, the page selector, Spotlight, menus), and list every element whose computed `border-top-style` is `outset`/`inset` or whose `background-color` is `rgb(239, 239, 239)` / `buttonface`, or `appearance` is `auto` on buttons/selects.

   - Number/text inputs -> `NumberField`/`TextField`.
   Do not hand-roll new native styling; if a component lacks a needed variant, add the variant to the component (design system first) and show it on the design system demos file of the lane.
