## Goal

Redesign the top bar so it is not a traditional "logo + File Edit View Window Help + right icons" strip. Pick the best layout you can within the rules below, and explain your choice in the handoff.

## Layout instruction (from Claude, as the user directed)

Direction: a **contextual toolbar**. One slim, full-width, square-edged strip whose middle section adapts to context, with a fixed left and right.

- **Left (fixed):** logo button that opens **one menu** holding File, Edit, View, Window and Help (use the existing menu model and commands, do not re-implement them). Next to it, the project name with the save-state dot and the copyable project ID.
- **Center (adaptive):** changes with context. Nothing selected: device switcher (Desktop / Tablet / Mobile), undo / redo. A layer selected: align and arrange actions. Reuse existing commands. If an adaptive state needs an engine hook that does not exist, **do not invent one**: ship the nothing-selected state and list the rest under "Engine changes requested" in `INTEGRATION.md`.
- **Right (fixed):** search / command palette entry (opens the existing `CommandPalette`), collaborators (`CollaboratorAvatarStack`), help, settings.
- **Showcase Demo toggle:** move it out of the bar into the logo menu. Keep its behaviour and test id working.

## Hard design constraints

- **Apple-level layout:** clear hierarchy, restraint, one spacing grid, strict alignment on a single baseline, large click targets, one icon stroke weight, consistent radii.
- **No capsules or pills.** No fully rounded buttons or containers. Rectangular shapes with modest radii from tokens.
- **No glass, blur or translucent materials.** Solid surfaces, hairline borders, soft shadows.
- **Colors and fonts: tokens only.** The neutral ramp is approved and is added to `tokens.css` by the earlier task `2026-10-30-neutral-tokens.md` (run first). Use only tokens from `src/editor/styles/tokens.css`, preferring the semantic ones, and `--font-sans`. The accent and state colors are not decided: use the existing tokens, add no new colors, and do not hardcode values. If you need a token that does not exist, list it in the handoff and `INTEGRATION.md` instead of editing `tokens.css`.
- **Motion:** only `transform` and `opacity`. Prefer CSS. One motion library per job, and the user has not assigned jobs yet, so use CSS only for now. The device switcher's active indicator may slide with `transform`. Respect `prefers-reduced-motion`.
- **Accessibility:** keyboard reachable, visible focus ring, labels on icon buttons, `aria-expanded` on the menu, Escape closes menus, text contrast at least 4.5:1.
- **Responsive:** desktop, tablet and mobile widths. At narrow widths the center section collapses without horizontal scroll.
