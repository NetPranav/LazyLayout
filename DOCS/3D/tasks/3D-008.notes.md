# 3D-008 Progress Notes: Transforms & hierarchy

## Step 1: Extend Object3d Schema in `src/core/document/scene3d.ts` & `src/core/document/schema.ts`
- **What**: Adding optional `parentInverse: number[16]` (`Mat4ArraySchema`) and optional `delta` `{ location?, rotationQuat?, scale? }` (`DeltaTransform3dSchema`) to `Object3dSchema`. Re-exporting these types in `schema.ts`.
- **Why**: Task 3D-008 requires parent-inverse matrices for Blender-compatible parenting without moving objects in world space, and delta transforms for additive local transformations.
- **Alternatives rejected**:
  - Making `parentInverse` or `delta` required: rejected because additive schema law and existing documents/fixtures must load identically without validation failures.
  - Using Zod tuple for 16 numbers instead of `z.array(z.number()).length(16)`: rejected because `z.array().length(16)` provides better TypeScript ergonomics with standard number arrays.

## Step 2: Create `src/core/3d/math.ts`
- **What**: Pure TypeScript implementation of 3D linear algebra (Vec3, Quat, Mat4 using column-major Float64Arrays adhering to glTF/WebGL standards). Implementing:
  - Identity, matrix multiplication, general 4x4 matrix invert (Laplace cofactor expansion), fast affine invert (upper 3x3 block + translation inversion).
  - TRS composition `compose(location, quat, scale)` and decomposition `decompose(m) -> { location, quat, scale }`.
  - Quaternion <-> Euler conversions `quatFromEuler(order, x, y, z)` and `eulerFromQuat(order, q)` for all six Tait-Bryan orders (`XYZ`, `XZY`, `YXZ`, `YZX`, `ZXY`, `ZYX`).
  - Quaternion multiplication, normalization, spherical linear interpolation (`slerp`).
  - Vector transformation: `transformPoint(m, p)` and `transformDirection(m, v)`.
- **Why**: Pure, deterministic, zero-dependency linear algebra kernel required for transform hierarchies, Blender-style matrix computations, and mesh transformations in `src/core/3d/`.
- **Alternatives rejected**:
  - Importing `gl-matrix` or `three`: rejected due to strict project law ("Core purity: code in `src/core/` must not touch the DOM or React. No new npm dependencies: write the small maths yourself").
  - 32-bit Float32Array: rejected because task specification explicitly specifies Float64 arrays for precision and glTF convention.
  - Row-major matrices: rejected because glTF, WebGL, and three.js all standardize on column-major matrices.

## Step 3: Create `src/core/3d/hierarchy.ts`
- **What**: Hierarchy traversal and parenting operations conforming to Blender's `parent_inverse` model:
  - `localMatrix(obj)`: combines base transform `{ location, rotationQuat, scale }` and optional `delta`.
  - `worldMatrix(doc, objectId)`: walks parent chain to root and evaluates transforms top-down: $W_{child} = W_{parent} \cdot P_{inv} \cdot M_{local}$.
  - `setParent(doc, childId, parentId, { keepWorld: true })`: detects cycles (throws when target is child or descendant of child), calculates $P_{inv} = W_{parent}^{-1} \cdot W_{child} \cdot M_{local}^{-1}$ to preserve exact world transform, and updates the document.
  - `clearParent(doc, childId, { keepWorld: true })`: unparents object and decomposes current world matrix back into local TRS when `keepWorld` is true.
  - `depth(doc, objectId)`: returns hierarchy depth (0 for root), checking for cycles.
- **Why**: Allows nested scene graphs where child objects follow parents without shifting when attached/detached, matching Blender's transform hierarchy contract.
- **Alternatives rejected**:
  - Recomputing local transform on parenting instead of using `parentInverse`: rejected because Blender standard explicitly uses `parentInverse: number[16]` so local coordinates/keyframes are undisturbed.
  - In-place mutation only: rejected; `setParent` and `clearParent` return updated documents while maintaining referential transparency.

## Step 4: Create `src/core/3d/apply.ts`
- **What**: Transform baking and origin manipulation while preserving world-space vertex positions:
  - `applyTransform(doc, objectId, { location, rotation, scale })`: bakes selected components into mesh positions/normals using $M_{bake} = M_{new}^{-1} \cdot M_{old}$ and resets the chosen transform fields.
  - `setOriginToGeometry(doc, objectId)`: relocates origin to geometry bounding box center, shifting vertices by $-O_{local}$ and updating object location by $R \cdot (S \cdot O_{local})$.
  - `setOriginToPoint(doc, objectId, point, { space })`: relocates origin to arbitrary world or local point, preserving world vertex positions.
  - `setOriginToCenterOfMass(doc, objectId)`: computes volume center using signed tetrahedra ($V_{tet} = \frac{1}{6} p_1 \cdot (p_2 \times p_3)$, $C_{tet} = \frac{p_1 + p_2 + p_3}{4}$), falling back to vertex mean for open meshes or zero-volume geometry.
- **Why**: Essential modeling and scene composition operations required by Phase 3D-008 and Blender workflows.
- **Alternatives rejected**:
  - Moving vertices without adjusting object location: rejected because prompt specifies "The visual object must not move: world positions of the vertices stay identical".
  - Approximating center of mass by simple vertex mean on closed meshes: rejected because prompt explicitly requires "mesh volume centre via signed tetrahedra; fall back to vertex mean for open meshes".

## Step 7: Fix `invertAffine` in `src/core/3d/math.ts`
- **What**: Fix the adjugate cofactor indexing in `invertAffine`. Previously, the cofactors of the 3x3 block were assigned with rows and columns transposed, which only worked for symmetric matrices and failed under non-uniform scaling / shearing. Recomputed the full 3x3 inverse matrix via adjugate $B_{i,j} = C_{j,i}/\det$ and computed translation as $-A^{-1} t$.
- **Why**: Ensures `invertAffine` matches `invert` exactly for any valid affine transformation with arbitrary rotation, translation, and non-uniform scale.
- **Alternatives rejected**: Using transpose of rotation assuming uniform scale: rejected because affine transforms include non-uniform scaling and skew.

## Step 8: Fix Top Face Index Winding in `createSampleCubeMesh` in `src/core/3d/__tests__/apply.test.ts`
- **What**: In `createSampleCubeMesh`, changed Top (+Y) face indices from `3, 2, 6,  3, 6, 7` (clockwise inward winding, normal $[0, -4, 0]$) to `3, 6, 2,  3, 7, 6` (counter-clockwise outward winding, normal $[0, +4, 0]$).
- **Why**: The signed-tetrahedra centroid formula requires consistent outward winding across all faces of the closed mesh. The single inverted face caused top-face tetrahedra to have negative volumes, corrupting the total volume sum and the volume-weighted centroid. With all 6 faces properly outward-oriented, the volume sums to +8 and the offset cube's center of mass evaluates to exactly $[5, -3, 2]$, correctly centering vertex 0 at $[-1, -1, -1]$ (`positions[0] === -1`) and vertex 6 at $[1, 1, 1]$ (`positions[18] === +1`).
- **Alternatives rejected**: Taking absolute values of each tetrahedron's volume: rejected because signed tetrahedra integration fundamentally relies on signed cancellations for non-convex shapes and arbitrary origin placement; proper manifold meshes must have consistent face orientation.
