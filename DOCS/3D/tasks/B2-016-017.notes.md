# Tasks B2-016-017 Progress Notes: Pure Transform and Snap Kernels

## Step 1: Create `src/core/3d/transform/typed.ts`
- **What**: Implement `parseTransformCommand(input: string)` returning `{ ok: boolean, mode?, axis?, plane: boolean, value?, error? }`. Supports Blender-style transform commands: "g x 2", "r z 90", "s 2", "g shift+z 1.5 enter", negative values, and robust error handling without throwing.
- **Why**: Phase 3D-016 requires a deterministic parser for modal G/R/S typed transform expressions and key sequences.
- **Alternatives rejected**:
  - Throwing an exception on invalid input: rejected because the specification explicitly requires "invalid input returns an error value (no throw)".
  - Regular expression only: rejected in favor of token-based parsing to handle whitespace variations, case insensitivity, combined modifiers like "shift+z", and trailing "enter" tokens cleanly.

## Step 2: Create `src/core/3d/transform/session.ts`
- **What**: Implement `TransformSession` and `createTransformSession` managing interactive modal transformations (translate, rotate, scale). Provides `moveMouse(dxPx, dyPx)` with depth-projected viewport motion, `setAxis("X"|"Y"|"Z", { plane })` with double-press global/local toggle, numeric buffer methods (`typeChar`, `backspace`, `negate`, `value`), `commit()` returning updated local transforms through parent inverses, and `cancel()` restoring original transforms.
- **Why**: Phase 3D-016 requires a deterministic, DOM-free transform session kernel handling modal operations matching Blender's G / R / S behaviors, parent hierarchies, and precise units (metres for translate, degrees typed and radians stored for rotate, unitless for scale).
- **Alternatives rejected**:
  - Recomputing transforms only on commit: rejected; internal state updates incrementally on each mouse or numeric change so UI overlays and properties can inspect live state.
  - Ignoring parent inverse matrices on commit: rejected because Blender-compatible hierarchy requires $M_{local} = W_{parentEffective}^{-1} \cdot W_{new}$ so child objects under rotated/scaled parents transform correctly in world space.

## Step 3: Create `src/core/3d/transform/gizmo.ts`
- **What**: Implement gizmo handle generation, ray hit testing, and dragging:
  - `gizmoHandles(mode, matrix, camera, sizePx)`: creates axis arrows, plane squares, rotation rings, and scale boxes with constant on-screen size via `sizePx`.
  - `hitGizmo(ray, handles)`: raycasting against line segments, planar squares, and circular rings, returning the closest handle id.
  - `dragGizmo(handle, rayStart, rayNow, startMatrix)`: computes the exact transform delta (axis-constrained closest point on line, plane intersection, or rotation ring angle).
- **Why**: Phase 3D-016 requires viewport gizmo math that remains scale-invariant on screen and allows precise direct-manipulation dragging.
- **Alternatives rejected**:
  - Approximating ring hit testing with coarse bounding boxes: rejected in favor of exact ray-plane intersection followed by radial distance thresholding for smooth, responsive cursor hovering.
  - Projecting gizmo to screen space before drag: rejected; computing in 3D world space using rays maintains sub-pixel precision and aligns with camera projection matrices.

- **Why**: Clean, unified public module entry point for transform features.
- **Alternatives rejected**: None. Follows project convention.

## Step 5: Create `src/core/3d/snap/snap.ts`
- **What**: Implement snapping primitives:
  - `snapValue(value, step)` for scalar increment snapping.
  - `snapToGrid(point, size)` for 3D grid snapping.
  - `snapToVertex(rayOrPoint, objects, radiusPx, viewProj)` for vertex snapping.
  - `snapToEdge(rayOrPoint, objects, radiusPx, viewProj)` for edge line-segment snapping.
  - `snapToFace(ray, objects)` for ray-triangle face snapping with surface normal calculation.
  - `alignToNormal(point, normal, upAxis)` computing a rotation quaternion aligning an object's up-axis to a surface normal.
  - `snapPoint(point, settings, scene)` combining enabled targets by priority: vertex > edge > face > grid > increment.
- **Why**: Phase 3D-017 requires pure 3D snapping calculations supporting magnetic cursor placement, surface attachment, and grid alignment.
- **Alternatives rejected**:
  - Relying on Three.js BVH classes inside core: rejected to keep `src/core/3d/` pure, deterministic, and free of runtime dependencies for basic mesh snapping.
  - Reversing priority order: rejected; standard 3D CAD/Blender convention strictly prioritizes highest topological feature specificity (vertex over edge over face over grid).

## Step 6: Create `src/core/3d/snap/pivot.ts`
- **What**: Implement `pivotPoint(kind, selection, cursor)` supporting all 4 pivot modes:
  - `"median"`: computes arithmetic mean of selection positions.
  - `"individual"`: returns an array of pivots, one for each selected object.
  - `"cursor"`: returns 3D cursor position.
  - `"active"`: returns the active (or last selected) object's position.
- **Why**: Phase 3D-017 requires flexible pivot points for rotational and scaling operations adhering to Blender standards.
- **Alternatives rejected**:
  - Forcing `"individual"` to return a single synthesized point: rejected because individual origins fundamentally requires per-object transformation origins.

## Step 7: Create `src/core/3d/snap/orientation.ts`
- **What**: Implement `orientationMatrix(kind, ctx)` returning a 4x4 rotation matrix for:
  - `"global"`: identity rotation (world X, Y, Z).
  - `"local"`: active object's rotation with scale removed.
  - `"normal"`: orthonormal basis aligning Z with the active face normal.
  - `"view"`: camera view axes (camera right, up, and back).
  - `"cursor"`: rotation matrix from the 3D cursor's quaternion.
- **Why**: Phase 3D-017 requires transform orientation spaces allowing gizmos and constraints to act relative to object local space, face normals, or the viewport camera.
- **Alternatives rejected**:
  - Returning 3x3 matrices: rejected because the rest of the 3D pipeline standardizes on 4x4 column-major `Mat4` Float64Arrays for seamless composition with `hierarchy.ts` and `math.ts`.

## Step 8: Create `src/core/3d/snap/cursor.ts`
- **What**: Implement 3D cursor management:
  - `Cursor3d` interface `{ position: Vec3, rotation: Quat }`.
  - `resetCursor()`: returns default cursor positioned at `[0, 0, 0]` with identity orientation `[0, 0, 0, 1]`.
  - `placeCursor(ray, scene)`: raycasts against scene meshes using `snapToFace`, aligns rotation to the hit surface normal via `alignToNormal`, and falls back to ground plane or ray distance on a miss.
- **Why**: Phase 3D-017 and 3D-019 require 3D cursor placement that sticks to surfaces upright for object insertion and pivot centering.
- **Alternatives rejected**:
  - Point-only cursor without rotation: rejected because placing objects at the cursor requires normal orientation alignment so objects sit upright on surfaces.
