## Entry 2: Adding `source` to `Mesh3dSchema` in `src/core/document/scene3d.ts` and `schema.ts`
- About to: Add `ProceduralSourceSchema` (`kind: z.string()`, `params: z.record(z.string(), z.unknown())`), export type `ProceduralSource`, and add optional `source` field to `Mesh3dSchema`. Re-export `ProceduralSource` and `ProceduralSourceSchema` in `src/core/document/schema.ts`.
- Why: Procedural meshes require storing the generator recipe on the `Mesh3d` data block so they can be re-evaluated and adjusted non-destructively.
- Alternative rejected: Storing procedural parameters on `Object3d` was rejected because the procedural recipe shapes the mesh data block, which can be shared across objects, matching Blender data-block architecture.

## Entry 3: Creating `src/core/3d/primitives/types.ts`
- About to: Create type definitions for the parametric primitive system: `PrimitiveKind`, `HandleDef`, `PrimitiveSpec<P>`, `PrimitiveMeshResult`.
- Why: Provides strict typed contracts for handles (id, label, position, axis, param, apply), primitive specifications, and geometry generation without any DOM or Three.js dependencies.
- Alternative rejected: Allowing loose `any` or untyped params was rejected to ensure TypeScript type safety and avoid ESLint warnings.
