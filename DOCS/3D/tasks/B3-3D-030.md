# Task 3D-030: Modifier stack (pure part and kernel hooks)
Read the "Phase 3D-030" entry in DOCS/INITIAL/ROADMAP_3D.md and decision 0019 notes in DOCS/INITIAL/ROADMAP_3D.md if any. Existing: `src/core/document/scene3d.ts` (Object3d), `src/core/kernel/evaluate3d.ts` and `src/core/3d/paths.ts` (3D property paths such as `3d:objects/<id>/modifiers/<modifierId>/<param>`), `src/core/jobs/` (worker pool: handlers in `handlers.ts`, `jobPool()`), `src/core/3d/commands/ops.ts` (typed commands; do NOT edit it).
1. Schema (additive in `scene3d.ts`): `Modifier3dSchema = {id, type: string, name?: string, enabled?: boolean (viewport), renderEnabled?: boolean, params: record<string, unknown>}` and `modifiers?: Modifier3d[]` on Object3d (the order is the stack order).
2. `src/core/3d/modifiers/registry.ts`: a registry of modifier definitions `{type, label, params zod schema with defaults, evaluate(mesh: MeshData, params) => MeshData}` where `MeshData = {positions: Float32Array, indices: Uint32Array, uvs?: Float32Array}` (pure, never mutating the input). Implement five: **mirror** (axis x/y/z, merge distance, bisect), **array** (count, relative or constant offset, merge), **solidify** (thickness, offset; closed shell with the original and an offset inner copy flipped), **transform** (translate, rotate degrees, scale applied to the vertices), **displace** (by a procedural noise: seeded value noise, strength, scale, midlevel; deterministic).
3. `src/core/3d/modifiers/stack.ts`: `evaluateStack(mesh, modifiers, {viewport: boolean})` (skips disabled by the right toggle), `stackKey(meshHash, modifiers)` and a small LRU cache so unchanged input is not recomputed, `applyModifier(doc, objectId, modifierId)` (bakes that modifier and everything below it? No: Blender applies one modifier, it must be first in the stack; refuse otherwise with a clear error) and `applyAll`; `reorderModifier`, `addModifier`, `removeModifier`, `setModifierParam` (all pure and immutable on the document). Heavy stacks evaluate in a worker: add a handler `modifiers.eval` to `src/core/jobs/handlers.ts` (additive: read the file) taking {mesh, modifiers} and returning MeshData with the buffers transferred, and `evaluateStackAsync` that uses `jobPool()` when the vertex count passes 50,000 and otherwise runs inline.
4. Kernel: modifier parameter tracks must evaluate: make sure `evaluate3D` (src/core/kernel/evaluate3d.ts) resolves `3d:objects/<id>/modifiers/<modifierId>/<param>` and exposes the evaluated `modifiers` for each object (additive; add tests; the 2D evaluate output must not change).
5. `commands.ts`: typed commands `3d.modifier.add`, `3d.modifier.remove`, `3d.modifier.reorder`, `3d.modifier.set_param`, `3d.modifier.set_visibility`, `3d.modifier.apply`, `3d.modifier.apply_all`; `register3dModifierCommands()` called next to `register3dCommands` (grep; additive). One undo step each.
6. Tests: stacks of 5 modifiers evaluate to golden meshes (hand-checked vertex counts and positions on a cube); reordering changes the result as specified (array then mirror differs from mirror then array); apply equals the evaluated result; disabled modifiers skipped per toggle; the cache hits on equal input; the worker handler's pure core function returns the same as inline (test the function directly); keyframed parameter evaluates at 3 times.
