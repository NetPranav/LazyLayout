# Task B2-014-015 Progress Notes
Phases 3D-014 (Navigation & Views) & 3D-015 (Selection in 3D)

## Step 1: Initializing Task and Plan
- **What:** Implementing pure core 3D camera navigation (`src/core/3d/camera/`) and selection/picking (`src/core/3d/pick/`) systems with deterministic unit tests.
- **Why:** Delivers viewport navigation (orbit, pan, dolly, standard views, gestures, tape) and raycasting, BVH acceleration, selection reducers, box/lasso picking, linked selection, and silhouette edge extraction according to ROADMAP_3D phases 3D-014 and 3D-015.
- **Alternatives Rejected:** Mixing DOM/React event listeners into `src/core/3d/`. Rejected because core purity laws require all camera mathematics and selection logic to be pure TypeScript with zero DOM/React coupling.

## Step 2: Creating `src/core/3d/camera/viewCamera.ts`
- **What:** Implementing immutable `ViewCamera` model, `orbit`, `pan`, `dolly`, `zoomToPoint`, `flyStep`, `viewMatrix`, `projectionMatrix`, `cameraPosition`, standard views (`front`, `back`, `left`, `right`, `top`, `bottom`), `toggleOrtho`, `frameBounds`, `frameAll`, and `viewFromObjectCamera`.
- **Why:** Delivers Phase 3D-014 core camera view math conforming to glTF 2.0 conventions (+Y up, -Z forward, right-handed) with Blender numpad standard views.
- **Alternatives Rejected:** Euler angles matrix rotation without pitch clamping. Rejected because pitch near +-90 degrees introduces gimbal lock and camera flipping; clamping pitch just short of +-90 degrees (`+- (PI/2 - 1e-4)`) preserves upright orientation and exact orbit invertibility.


## Step 3: Creating `src/core/3d/camera/gestures.ts`
- **What:** Implementing `navigationFromGesture(event)` mapping pointer/touch events to navigation actions (orbit, pan, dolly).
- **Why:** Delivers Phase 3D-014 pure gesture mapping without DOM/browser dependencies, translating mouse middle drag, trackpad scroll/pinch, and touch gestures into standard navigation deltas.
- **Alternatives Rejected:** Direct DOM `PointerEvent` or `TouchEvent` listeners in core. Rejected because core must stay pure and testable across node and web workers.

## Step 4: Creating `src/core/3d/camera/tape.ts`
- **What:** Implementing `TapeStep` definition and `runTape(cam0, tape)` replay interpreter for camera operations.
- **Why:** Delivers Phase 3D-014 deterministic navigation tape execution for automated test verification and macro replays.
- **Alternatives Rejected:** Mutable camera state machine. Rejected because immutable `ViewCamera` functional folds guarantee referential transparency and predictable undo/redo replay.

## Step 5: Creating `src/core/3d/pick/ray.ts`
- **What:** Implementing `rayFromScreen(x, y, viewportW, viewportH, viewMatrix, projMatrix)` returning `{ origin, dir }` for both perspective and orthographic projections.
- **Why:** Delivers Phase 3D-015 ray generation from screen coordinates via inverted view-projection transformation and perspective division.
- **Alternatives Rejected:** Branching on camera type. Unprojecting NDC near (-1) and far (+1) coordinates through `inv(Proj * View)` naturally and unifiedly handles both perspective and orthographic cameras without special-casing.

## Step 6: Creating `src/core/3d/pick/bvh.ts`
- **What:** Implementing `pickMesh`, `pickScene`, and mesh BVH caching per `(meshId, version)` using `three-mesh-bvh`.
- **Why:** Delivers Phase 3D-015 high-performance accelerated ray-mesh picking, local-to-world transform handling with normal matrix transposition, and distance-sorted scene hits.
- **Alternatives Rejected:** Naive brute-force triangle intersection. Rejected because $O(N)$ raycasting across 100,000 faces takes >20 ms per ray, whereas BVH spatial acceleration achieves $O(\log N)$ (<0.05 ms per ray).

## Step 7: Creating `src/core/3d/pick/select.ts`
- **What:** Implementing `Selection3d` reducer, `click`, `selectAll`, `selectNone`, `invert`, `boxSelect`, `lassoSelect`, `selectLinked`, `selectSimilar`, and face-level `selectLinkedFaces`.
- **Why:** Delivers Phase 3D-015 selection engine with Blender-standard click semantics, geometric projection picking (box and lasso), hierarchy/data-linking traversal, and mesh face connectivity flood-fill.
- **Alternatives Rejected:** Mutating an external selection set. Rejected because immutable functional reducers ensure clean time-travel debugging, undo/redo compatibility, and command isolation.

## Step 8: Creating `src/core/3d/pick/outline.ts`
- **What:** Implementing `silhouetteEdges(positions, indices)` returning edge vertex endpoints and dual adjacent face normals for the outline shader pass.
- **Why:** Delivers Phase 3D-015 edge adjacency extraction where silhouette detection (one face pointing towards camera and one pointing away, or open mesh boundary) can be performed rapidly in the outline pass.
- **Alternatives Rejected:** Computing dynamic view-dependent silhouettes entirely on the CPU per frame. Rejected because doing static edge adjacency extraction on the CPU and evaluating `dot(n0, view) * dot(n1, view) <= 0` in the outline shader is dramatically faster.

## Step 9: Creating `src/core/3d/__tests__/camera.test.ts`
- **What:** Implementing unit tests for Phase 3D-014: `viewCamera`, standard views, `toggleOrtho`, `frameBounds`, `viewFromObjectCamera`, `gestures`, and a 15-step navigation tape with hand-computed golden matrix and orbit invertibility within 1e-12.
- **Why:** Proves correctness of camera projection, coordinate system conventions, gesture translations, and determinism under tape replay.
- **Alternatives Rejected:** Calling the camera functions under test to generate expected values in the tape test. Rejected because prompt strictly requires computing expected values by hand from analytical mathematics.

## Step 10: Creating `src/core/3d/__tests__/pick.test.ts`
- **What:** Implementing unit tests for Phase 3D-015: `rayFromScreen`, 30 analytical test views hitting a known cube, 100,000-face picking benchmark (<3 ms/ray), selection reducer cases (click, shift, ctrl, selectAll, selectNone, invert), `boxSelect`, `lassoSelect`, `selectLinked`, `selectSimilar`, `selectLinkedFaces`, and `silhouetteEdges`.
- **Why:** Verifies ray intersection precision against analytic ground truths within 1e-6, ensures spatial index efficiency under high polygon counts, and proves full selection reducer correctness.
- **Alternatives Rejected:** Testing only coarse bounding-sphere hits. Rejected because three-mesh-bvh triangle intersection and face-level topology connectivity require exact mesh geometry validation.
