# Task 3D-008: Transforms & hierarchy
Needs 3D-007 (the `objects` table, Object type with transform/parent). Read the "Phase 3D-008" entry in DOCS/INITIAL/ROADMAP_3D.md.

Create `src/core/3d/` (pure TypeScript, no dependencies) with:
- `math.ts`: Vec3, Quat, Mat4 (column-major Float64 arrays, glTF convention), functions: identity, multiply, invert (general 4x4 + fast affine), compose(location, quat, scale), decompose(m) -> {location, quat, scale}, quatFromEuler(order, x, y, z) / eulerFromQuat(order, q) for all six orders XYZ XZY YXZ YZX ZXY ZYX, quat multiply/normalize/slerp, transformPoint, transformDirection.
- `hierarchy.ts`: `worldMatrix(doc, objectId)` (walks parent chain with each object's `parentInverse` matrix (add optional `parentInverse: number[16]` and optional `delta` {location, rotationQuat, scale} to the Object schema in scene3d.ts if 3D-007 did not already; keep optional so old data loads), `setParent(doc, childId, parentId, {keepWorld: true})` which computes parentInverse so the world matrix is unchanged, `clearParent(doc, childId, {keepWorld: true})`, cycle detection (throw on parenting an object under its own descendant), `depth`.
- `apply.ts`: `applyTransform(doc, objectId, {location, rotation, scale})` bakes the chosen parts into the object's mesh positions and resets the transform; `setOriginToGeometry`, `setOriginToPoint(point)`, `setOriginToCenterOfMass` (mesh volume centre via signed tetrahedra; fall back to vertex mean for open meshes). The visual object must not move: world positions of the vertices stay identical.
Tests (`src/core/3d/__tests__/*.test.ts`): hand-computed golden world matrices through a 4-level hierarchy; parenting and unparenting keep the world matrix within 1e-6; quat/euler round-trips for all six orders at a spread of angles (avoid exactly gimbal-locked cases or test them separately); compose/decompose round-trip; applyTransform and origin changes keep world-space vertices within 1e-9; cycle rejected.
