# Tasks 3D-021 (Outliner model) and 3D-024 (Shared data blocks & copy attributes): pure parts
Read the "Phase 3D-021" and "Phase 3D-024" entries in DOCS/INITIAL/ROADMAP_3D.md. Existing: `src/core/document/scene3d.ts` (Scene3d, Object3d with `parent`, `data`, `materialSlots`, `visible`...), `dataBlocks.ts` (userCount, makeSingleUser, removeUnused), `src/core/3d/hierarchy.ts` (worldMatrix, setParent with keepWorld, clearParent), `src/core/3d/commands/ops.ts` (the typed 3D commands and `run3dOp`; read how ops are shaped, do NOT edit that file: add new files).
Add additive optional fields in `scene3d.ts` (no schema version bump; old documents must load): on Object3d `selectable?: boolean` (default true), `renderVisible?: boolean` (default true), `collection?: string` (a collection id); on Scene3d `collections?: Record<string, {id: string; name: string; parent?: string | null; visible?: boolean; selectable?: boolean; renderVisible?: boolean}>`.
1. `src/core/3d/outliner/tree.ts`: `buildOutliner(doc, sceneId): OutlinerNode[]`: a tree of nodes {id, kind: "collection"|"object"|"data"|"material"|"modifier", label, icon key (string), children, flags {visible, selectable, renderVisible}, depth}. Objects nest by `parent`; an object's data block (mesh/light/camera/armature), material slots and modifiers (the `modifiers` array on Object3d if present: read defensively; a parallel task adds it) are leaf children. Collections group objects; objects in no collection sit at the scene root. `flattenVisible(tree, expandedIds)` for list rendering; `findNode`, `pathTo`.
2. `src/core/3d/outliner/ops.ts` (pure, immutable `(doc, args) => doc`): `setFlag(doc, id, flag, value)` (hiding a collection hides what is in it for display; the stored flag stays on the collection), `reparent(doc, objectId, newParentId | null, {beforeId?})` (keeps the world transform to 1e-6 via setParent/clearParent keepWorld; refuses a cycle with a clear error), `moveToCollection`, `createCollection`, `renameNode`, `deleteNode`. Each must not mutate its input (clone first).
3. `src/core/3d/outliner/commands.ts`: register typed commands `3d.outliner.set_flag`, `3d.outliner.reparent`, `3d.outliner.move_to_collection`, `3d.outliner.create_collection`, `3d.outliner.rename`, category "3D", through `defineTypedCommand`, one undo step each; export `register3dOutlinerCommands()` and call it next to `register3dCommands` (grep where that is called; additive call).
4. 3D-024 in `src/core/3d/blocks/`: `userCounts(doc)` (a table of counts for every shared block kind), `copyAttributes(doc, fromObjectId, toObjectIds, parts: Array<"material"|"modifiers"|"transform"|"visibility">)` (material shares the block by id (+1 user); modifiers are cloned with new ids; transform copies location/rotation/scale only) and the typed commands `3d.blocks.copy_attributes` and `3d.blocks.make_single_user` (wrapping the existing makeSingleUser for material, mesh and action; extend `dataBlocks.ts`'s makeSingleUser only additively if mesh/action are missing).
5. Tests (node:test, pure): tree shape for a nested scene with collections; golden world matrices before/after reparent through 4-level hierarchies (1e-6); cycle refused; flags; the tree mirrors the document both ways (apply an op, rebuild, compare); user counts exact under 200 random operations (seeded generator: assign material, make single user, delete object, duplicate, copy attributes) compared with a brute-force recount; undo restores sharing (run through the real history like `src/core/3d/commands/__tests__/commands3d.test.ts` does).
