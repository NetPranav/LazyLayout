## 2. Public API Added
- `useViewportStore`: Zustand store hook providing `{ settings, camera, selection, cursor, snap, pivot, orientation, keymapId, editingSceneId, setSettings, setCamera, setSelection, setCursor, setSnap, setPivot, setOrientation, setKeymapId, setEditingSceneId, reset }`.
- `createInitialViewportState()`: Returns fresh default viewport state record.
- `buildScene(doc, sceneId)`: Builds a `BuiltScene` containing Three.js scene, perspective camera, ambient light, and cached object/geometry/material maps.
- `applyEvaluated(builtScene, evaluated3D)`: Applies transforms, material properties, lights, and camera updates from `evaluate3D` deterministically.
- `disposeThreeObject(obj)`: Cleans up geometry and material GPU buffers for a Three.js object.
- `createBufferGeometry(meshData)`: Converts an MDM `Mesh3d` into a `THREE.BufferGeometry`.
- `createStandardMaterial(matData)`: Creates a `THREE.MeshStandardMaterial` from `Material3d`.
- `updateStandardMaterial(mat, matData)`: Mutates a `THREE.MeshStandardMaterial` in place with updated `Material3d` properties.
- `applyShading(scene, settings, renderer, camera)`: Applies shading mode, 3-point studio lighting, RoomEnvironment HDRI, renderedHook, and X-ray transparency.
- `createStudioLights()`: Returns a Three.js group with Key, Fill, Rim directional lights and ambient light.
- `getOrCreateRoomEnvironment(renderer)`: Returns cached PMREM RoomEnvironment texture.
- `createWireframeMaterial(color)`: Returns a wireframe `THREE.MeshBasicMaterial`.
- `createSolidCavityMaterial(options)`: Returns a `THREE.ShaderMaterial` compiled from `viewport/shaders.ts`.
- `renderedHook`: Mutable hook function called during "rendered" shading mode.
- `setRenderedHook(hook)`: Registers or clears the `renderedHook`.
- `SceneView`: React component managing WebGLRenderer lifecycle, compositor registration, and frameScheduler rendering.
- `Scene3dLayer`: `ArchetypeRenderProps` React component providing lazy-loading wrapper and double-click editing entry for `scene3d`.
- `insert3dScene(args)`: Inserts a new 3D scene (cube, camera, light) and `scene3d` layer into the document in a single atomic undo step.
- `buildDefaultSceneData()`: Generates fresh data blocks for a default 3D scene with cube, camera, and light.
- `registerSceneCommands()`: Registers `3d.scene.insert` and `3d.scene.exit` with the command bus.
- `setEditingScene3d(editing)`: Sets the `editingScene3d` context key in `useContextKeysStore`.

## 3. Decisions Made
1. **Lazy Loading of Three.js via Dynamic Import**: `Scene3dLayer` uses `React.lazy(() => import("../scene3d/SceneView"))` with Suspense. Pages with 0 3D scenes incur 0 bundle size or runtime execution penalty for Three.js.
2. **On-Demand Frame Scheduling**: Rather than running an unconstrained `requestAnimationFrame` loop, `SceneView` schedules a single render pass via `frameScheduler.register("render", ...)` only when state is dirtied (document mutation, transport time scrub, camera movement, shading change, or waking from sleep). It unregisters the task immediately upon drawing. Idle scenes cost 0 frames.
3. **Compositor Integration & Poster Fallback**: Implemented the full `compositor.registerScene` contract: `onReady` creates/restores the `THREE.WebGLRenderer`, `onRelease` copies the canvas to a 2D poster canvas and disposes WebGL resources, and `IntersectionObserver` reports visibility so off-screen scenes sleep and free their WebGL context.
4. **Unified Command Integration**: Placed `3d.scene.insert` and `3d.scene.exit` in `src/core/3d/commands/sceneInsert.ts` without touching parallel-authored files. Registered them in `src/core/editing/editCommands.ts` alongside `register3dCommands()`.
5. **Context Key Guard for Exit**: `3d.scene.exit` uses `when: (ctx) => Boolean(ctx.editingScene3d)` bound to keybinding `"Escape"`. `useViewportStore` automatically updates `useContextKeysStore` whenever `editingSceneId` transitions between null and a scene ID.
