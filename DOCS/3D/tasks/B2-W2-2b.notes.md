## Creating src/core/3d/keymap/bind.ts
- About to: Create `src/core/3d/keymap/bind.ts` exporting `bindKeymap(keymap: Keymap)` and `formatKeyBindingShortcut(binding: KeyBinding)`.
- Why: Requirement 5 of Task B2-W2-2b. Sets the `keybinding` of every registered `3d.*` command through the central command registry (`defineCommand`), gating execution on `!ctx.textEditing && Boolean(ctx.editingScene3d)` according to the keymap's context. When keymap switches, commands bound in the previous keymap but unassigned in the new one have their `keybinding` cleared (`undefined`). Keys appear in View > Show keystrokes automatically through the command bus.
- Alternatives rejected: Adding a custom keydown listener that bypasses the command registry. Bypassing the registry would break ScreencastKeys (View > Show keystrokes), break conflict inspection, and break parity between shortcut execution and palette/command invocations.

## Creating src/core/render/scene3d/overlays.ts
- About to: Create `src/core/render/scene3d/overlays.ts` implementing Three.js overlay rendering for the 3D viewport.
- Why: Requirement 4 of Task B2-W2-2b. Supports:
  1. Ground grid on XY plane (Z = 0) fading with distance.
  2. Colored axes lines (X red, Y green, Z blue).
  3. Object origins as dots.
  4. Face orientation using `FACE_ORIENTATION_VERTEX_SHADER` and `FACE_ORIENTATION_FRAGMENT_SHADER` (blue front / red back).
  5. Vertex / face normal lines.
  6. Wireframe on shaded overlay.
  7. 3D cursor (red-white alternating ring and crosshair).
  8. Selection outline using `OUTLINE_VERTEX_SHADER` and `OUTLINE_FRAGMENT_SHADER` with color read once from CSS variable (`--ll-pen-mark` / `--ll-label-4`).
- Alternatives rejected: Rebuilding all overlay objects on every frame from scratch. Maintaining persistent, cached sub-objects inside an `__overlays__` group and updating transforms and visibility preserves GPU buffer allocation and avoids garbage-collection frame spikes.
