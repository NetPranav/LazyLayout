## Public API Added

### Outliner Model (`src/core/3d/outliner/`)
- `buildOutliner(doc: MotionDocument, sceneId: string): OutlinerNode[]`: Builds a hierarchical tree of collection and object nodes, with data blocks, material slots, and modifiers as leaf children, resolving display flags.
- `flattenVisible(tree: OutlinerNode[], expandedIds: Iterable<string>): OutlinerNode[]`: Flattens the visible tree rows for list rendering based on an expanded node set.
- `findNode(tree: OutlinerNode[], id: string): OutlinerNode | null`: Recursively searches the tree for a node matching the given id.
- `pathTo(tree: OutlinerNode[], id: string): OutlinerNode[] | null`: Returns the array of `OutlinerNode` items from root to target node, or null if not found.
- `pathIdsTo(tree: OutlinerNode[], id: string): string[] | null`: Returns the array of node IDs from root to target node, or null if not found.
- `setFlag(doc: MotionDocument, id: string, flag: OutlinerFlag, value: boolean): MotionDocument`: Pure immutable setter for visibility, selectability, or render visibility on collections and objects.
- `reparent(doc: MotionDocument, objectId: string, newParentId: string | null, options?: { beforeId?: string }): MotionDocument`: Pure immutable reparenting that preserves world matrix within 1e-6 tolerance and detects cycles with descriptive errors.
- `moveToCollection(doc: MotionDocument, objectId: string, collectionId: string | null): MotionDocument`: Pure immutable movement of an object into or out of a collection.
- `createCollection(doc: MotionDocument, sceneId: string, options?: { id?: string; name?: string; parent?: string | null }): MotionDocument`: Pure immutable creation of a new collection in a scene.
- `renameNode(doc: MotionDocument, id: string, newName: string): MotionDocument`: Pure immutable renaming of collections, objects, materials, meshes, lights, cameras, armatures, and actions.
- `deleteNode(doc: MotionDocument, id: string): MotionDocument`: Pure immutable deletion of collections (unlinking contents) or objects (unparenting children).
- `register3dOutlinerCommands(): () => void`: Registers typed commands `3d.outliner.set_flag`, `3d.outliner.reparent`, `3d.outliner.move_to_collection`, `3d.outliner.create_collection`, and `3d.outliner.rename`.

### Shared Data Blocks & Copy Attributes (`src/core/3d/blocks/`)
- `userCounts(doc: MotionDocument): UserCountsTable`: Pure single-pass reference counter returning `{ materials, meshes, lights, cameras, armatures, actions, worlds, images3d, objects, scenes }` tables matching `userCount` semantics.
- `copyAttributes(doc: MotionDocument, fromObjectId: string, toObjectIds: string[], parts: AttributePart[]): MotionDocument`: Pure immutable attribute copier: shares materials by ID (+1 user), clones modifiers with fresh IDs, copies TRS-only transforms, and copies visibility flags.
- `register3dBlocksCommands(): () => void`: Registers typed commands `3d.blocks.copy_attributes` and `3d.blocks.make_single_user`.

### Schema & Data Blocks Extensions (`src/core/document/`)
- `Collection3dSchema`: Zod schema for 3D collections `{ id, name, parent?, visible?, selectable?, renderVisible? }`.
- `Collection3d`: Type definition for 3D collection records.
- `makeSingleUser(doc: MotionDocument, objectId: string, target?: SingleUserTarget, slot?: number): MotionDocument`: Additively extended to support material slots, meshes, and actions.

## Decisions Made
1. **Effective flags vs stored flags in Outliner**:
   - As specified ("hiding a collection hides what is in it for display; the stored flag stays on the collection"), `buildOutliner` computes effective flags for display (`parentFlags.visible && storedVisible`), while preserving raw stored flags on `storedFlags`. In `setFlag`, only the targeted collection or object record in the document is updated; children do not have their stored properties mutated.
2. **Deterministic World Matrix Preservation in Reparenting**:
   - `reparent` uses `setParent` / `clearParent` with `keepWorld: true`, preserving world matrix to `1e-6` precision, verified through 4-level deep hierarchies.
3. **Cycle detection**:
   - `reparent` explicitly traverses ancestor chains before mutating and raises a clear descriptive error (`Cannot parent object "A" under its own descendant "B" (cycle detected)`).
4. **Single-pass userCounts**:
   - Rather than scanning the entire document for every individual block, `userCounts(doc)` seeds all known block keys to 0 and counts references across objects, scenes, layers, materials, and worlds in a single O(N) pass, strictly mirroring `userCount` logic from `dataBlocks.ts`.
5. **Backwards-compatible `makeSingleUser`**:
   - Preserved signature `(doc, objectId, slot: number)` as the default material branch, while allowing `target: "mesh" | "action" | { kind: "material", slot }`.
