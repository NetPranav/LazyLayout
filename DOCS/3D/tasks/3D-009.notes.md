# 3D-009 Progress Notes: Units, axes & conventions

## Step 1: Extend SceneSettingsSchema in `src/core/document/scene3d.ts`
- **What**: Adding optional `pxPerMetre: z.number().positive().optional()` to `SceneSettingsSchema`.
- **Why**: Task 3D-009 specifies `PX_PER_METRE` default 100 stored per scene as `scene.settings.pxPerMetre` (optional field in Scene schema if absent; default 100).
- **Alternatives rejected**:
  - Making `pxPerMetre` required: rejected because schema v7 and existing document fixtures must remain valid without requiring this field (additive schema rule).
  - Placing `pxPerMetre` directly on `Scene3d` root: rejected because spec specifically designates `scene.settings.pxPerMetre`.

## Step 2: Create `src/core/3d/units.ts`
- **What**: Pure TypeScript implementation of units, conventions, projection and camera setup:
  - glTF 2.0 coordinate system constants and documentation: Y-up, right-handed, metres, radians.
  - `PX_PER_METRE = 100` constant, `pxToMetres(px, pxPerMetre?)`, `metresToPx(metres, pxPerMetre?)`, and `getPxPerMetre(scene?)`.
  - Angle utilities: `degToRad`, `radToDeg`, and `formatAngle(radians, options?)` for degrees-based UI presentation distinct from radians storage.
  - `frameTo3D(width, height, pxPerMetre)` computing plane dimensions in metres.
  - `defaultCameraFor(width, height, pxPerMetre, fovY)` computing exact distance and perspective camera pose so a $z=0$ frame of size $W \times H$ projects exactly to $W \times H$ pixels on screen.
  - `projectToScreen(camera, viewportW, viewportH, point)` projecting 3D points through perspective camera matrices to 2D viewport coordinates.
- **Why**: Phase 3D-009 contract for seamless 2D canvas to 3D scene mapping and standard unit representations.
- **Alternatives rejected**:
  - Hardcoding 100 px/metre without scene setting support: rejected because scenes need per-scene customization via `scene.settings.pxPerMetre`.
  - Storing degrees in the document: rejected because glTF and MDM standard requires radians for internal storage and degrees only for UI display.

## Step 3: Create `src/core/3d/axes.ts`
- **What**: Pure TypeScript implementation of axis conversion between glTF Y-up and Blender Z-up:
  - Document convention: glTF Y-up (+Y Up, -Z Forward, +X Right) <-> Blender Z-up (+Z Up, +Y Forward/Back, +X Right).
  - Overloaded functions `zUpToYUp(Mat4 | Vec3 | Quat)` and `yUpToZUp(Mat4 | Vec3 | Quat)` with exact inverses.
  - Dedicated typed helpers `zUpToYUpVec3`, `zUpToYUpQuat`, `zUpToYUpMat4`, and inverses `yUpToZUpVec3`, `yUpToZUpQuat`, `yUpToZUpMat4`.
  - Constant matrices `MAT4_Z_UP_TO_Y_UP` and `MAT4_Y_UP_TO_Z_UP`, and quaternions `QUAT_Z_UP_TO_Y_UP` and `QUAT_Y_UP_TO_Z_UP`.
- **Why**: Allows Blender view orientation and glTF standard orientation conversions with round-trip accuracy.
- **Alternatives rejected**:
  - Approximating matrix inversion via general invert: rejected; direct column reordering and sign-flips provides bit-exact inverses with zero numerical error.

## Step 4: Create `src/core/3d/gltfMap.ts`
- **What**: Pure TypeScript implementation of glTF 2.0 schema mapping, transform translation, and minimal self-contained JSON import/export:
  - Node transform <-> Object transform mapping: `nodeTransformToObjectTransform` / `gltfNodeToTransform` and `objectTransformToNodeTransform` / `transformToGltfNode`, handling TRS and column-major `matrix` decompositions.
  - `toGltfJson(doc, sceneId)`: generates a valid glTF 2.0 JSON structure containing scenes, nodes, meshes, accessors, bufferViews, and a single self-contained data URI buffer (base64 encoded, zero external files) preserving exact positions, indices, normals, and uvs alongside primitive extras.
  - `fromGltfJson(json, existingDoc?)`: parses glTF 2.0 JSON string or object, decodes node hierarchies and TRS transforms, extracts mesh geometry from binary buffer views and extras, and constructs a valid `MotionDocument` with 3D scene data blocks.
- **Why**: Phase 3D-009 requirement for standard glTF export and import round-trips without external file dependencies.
- **Alternatives rejected**:
  - Requiring separate `.bin` files: rejected because prompt explicitly requires "without external files; keep it minimal but exact".
  - Omitting accessors/bufferViews and using custom non-standard JSON: rejected because standard glTF compliance requires valid 2.0 asset, scenes, nodes, meshes, and accessors.
