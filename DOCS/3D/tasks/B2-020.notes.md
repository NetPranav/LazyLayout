# Task B2-020: 3D Keymaps and Viewport Core Data Notes

## Initial Setup
- Initialized running notes for task B2-020.
- Scope: Keymaps (Blender, Beginner, conflict detection, resolution) under `src/core/3d/keymap/` and Viewport settings, scene statistics, and GLSL shaders under `src/core/3d/viewport/`.

## Creating `src/core/3d/keymap/types.ts`
- **What**: Define `KeyBinding`, `KeymapContext`, `KeymapId`, `Keymap`, and canonical command ID constants.
- **Why**: Provides the type contract required by Phase 3D-020 and shared across keymap modules.
- **Alternatives rejected**: Using ad-hoc strings for contexts or omitting strict typing on Keymap ID.

## Creating `src/core/3d/keymap/blender.ts`
- **What**: Implement Blender keymap bindings matching Phase 3D-020 spec:
  - Modal transforms: G, R, S
  - Mode: Tab
  - Numpad views: 1, 3, 7 (front, right, top), Ctrl+1/3/7 (back, left, bottom), 5 (toggle ortho), . (frame selected), Home (frame all), 0 (camera view)
  - Menu & edit: Shift+A (add menu), X / Delete (delete), H (hide), Alt+H (unhide all)
  - Selection: A (select all), Alt+A (none), Ctrl+I (invert), L (select linked), Shift+G (similar), B (box)
  - Hierarchy: Shift+D (duplicate), Ctrl+P (parent), Alt+P (unparent)
  - Shading & cursor: Shift+Z (wireframe), Alt+Z (x-ray), Shift+C (reset cursor), Shift+mouse2 (place cursor)
- **Why**: Allows Blender muscle-memory users to operate the 3D viewport without friction.
- **Alternatives rejected**: Binding arbitrary letters to 4 shading modes (spec notes letter keys for 4 shadings are not bound; Shift+Z is wireframe toggle).

## Creating `src/core/3d/keymap/beginner.ts`
- **What**: Implement Beginner keymap preset:
  - Simple unshifted keys in `context: "object"`:
    - V: `3d.transform.translate`
    - R: `3d.transform.rotate`
    - S: `3d.transform.scale`
    (Scattered in `object` context so they do not collide with 2D editor tools or global shortcuts).
  - Common editor conventions: Delete / Backspace (`3d.object.delete`), Ctrl+D (`3d.object.duplicate`), Ctrl+A (`3d.select.all`), Escape (`3d.select.none`), Tab (`3d.mode.toggle_edit`), F (`3d.view.frame_selected`), Home (`3d.view.frame_all`), Z (`3d.shading.wireframe`), Shift+Z (`3d.shading.toggle_xray`).
  - `toolbarOnly: true` list covering all remaining canonical 3D commands, guaranteeing beginners can access all 3D features via UI buttons without needing keyboard shortcuts.
- **Why**: Fulfils Phase 3D-020 requirement that "beginners never need a key" while maintaining natural familiarity.
- **Alternatives rejected**: Mapping all 60 commands to keyboard shortcuts, which would create unnecessary memorization and shortcut collisions.

## Creating `src/core/3d/keymap/conflicts.ts`
- **What**: Implement conflict detection (`findConflicts`) and event resolution (`resolve`):
  - `findConflicts(keymap)`: detects any duplicate binding with matching key and modifiers in overlapping contexts (where `global` overlaps all contexts).
  - `resolve(keymap, event, context)`: matches a keyboard or mouse event against active bindings in the given context, preferring specific context over `global`.
- **Why**: Ensures keymaps remain conflict-free and can dispatch keystrokes reliably.
- **Alternatives rejected**: Case-sensitive key comparisons (e.g., "x" vs "X") which could cause false negatives across platforms.

## Creating `src/core/3d/keymap/index.ts`
- **What**: Re-export public types, constants, keymaps (`blenderKeymap`, `beginnerKeymap`), conflict detector (`findConflicts`), and resolver (`resolve`).
- **Why**: Clean module barrel for `src/core/3d/keymap`.
- **Alternatives rejected**: None.

## Creating `src/core/3d/viewport/settings.ts`
- **What**: Define `ShadingMode`, `ViewportSettings` schema & defaults, a pure reducer for shading/overlay commands, and zod (de)serialization.
- **Why**: Viewport state must be deterministic, pure, and reactive without DOM dependencies.
- **Alternatives rejected**: Mutable settings objects or coupling reducer actions to UI components.

## Creating `src/core/3d/viewport/stats.ts`
- **What**: Implement `sceneStats(doc, sceneId)` returning `{ objects, vertices, faces, triangles, estimatedMemoryBytes }`.
  - Traverses `doc.scenes[sceneId].objects` and inspects mesh data blocks (inline positions/indices/normals/uvs and binary refs).
  - Employs coplanar adjacent triangle clustering (union-find) so quad-based models like the standard cube evaluate to 8 vertices, 6 faces, 12 triangles.
  - Computes byte size based on 4-byte Float32/Uint32 buffers.
- **Why**: Viewport statistics overlay requires fast, deterministic scene statistics directly from MDM data blocks.
- **Alternatives rejected**: Approximating faces simply as `triangles / 2`, which would fail on arbitrary triangle meshes.

## Creating `src/core/3d/viewport/shaders.ts`
- **What**: Provide WebGL2 / GLSL 3.00 ES shader constants for viewport shading:
  1. Solid shader: studio 3-point lighting + curvature-based cavity darkening.
  2. Wireframe-on-shaded shader: barycentric antialiased wireframe.
  3. Normal-visualization shader: world-space normal mapped to RGB.
  4. Face-orientation shader: front blue (`gl_FrontFacing`), back red.
  5. Selection outline shader: inverted hull expansion along normal.
  - Implement `uniformsFor(mode, settings)` returning plain uniform values.
- **Why**: Viewport rendering requires self-contained GLSL constants with explicit `#version 300 es` and documented uniform contracts.
- **Alternatives rejected**: Generating GLSL strings dynamically via complex string concatenation.
