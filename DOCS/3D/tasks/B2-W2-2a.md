# Tasks 3D-014..3D-017 hooked into the viewport (interaction layer)
Read the entries "3D-014" to "3D-017" in DOCS/INITIAL/ROADMAP_3D.md and `DOCS/UI/UI_RULES.md`. The pure logic exists already (read its exports with grep, do not edit it): `src/core/3d/camera/` (ViewCamera, orbit/pan/dolly/views/gestures/tape), `src/core/3d/pick/` (ray, BVH picking, Selection3d, box/lasso), `src/core/3d/transform/` (TransformSession, typed parser, gizmo handles/hit/drag), `src/core/3d/snap/` (snapping, pivot, orientation, Cursor3d). The shared store is `src/core/render/scene3d/viewportStore.ts` and the scene view is `src/core/render/scene3d/SceneView.tsx` (from the previous task; read them). Command ids: B2-ids.md.
Build `src/editor/viewport3d/`:
1. `ViewportInteraction.tsx`: a transparent layer over the scene canvas while `editingSceneId` is set. Pointer events (React `onPointerDown/Move/Up/Wheel`, pointer capture; NO raw `window.addEventListener('keydown')` and no requestAnimationFrame: eslint forbids both) map through `gestures.ts` to camera navigation, update the store's camera and re-render; a click picks through `pickScene` and updates `selection`; drag on empty space does box select; Shift adds; Alt/lasso per the roadmap.
2. Gizmo overlay `GizmoOverlay.tsx` (SVG over the canvas, constant pixel size) driven by `gizmoHandles`; dragging uses `dragGizmo`; one undo step per gesture through a 3D command (`3d.object.set_location/rotation/scale`) committed on pointer up; Escape / right-click cancels (the transform returns to the original exactly).
3. Modal G/R/S: commands `3d.transform.translate|rotate|scale` start a `TransformSession`; while a session is active the viewport element holds focus and a React `onKeyDown` on it feeds X/Y/Z, Shift, digits, `.`, `-`, Backspace, Enter, Escape into the session and the mouse moves update it; a small status line shows e.g. "Move X 2.00 m". Enter commits (one undo step through the object commands, which already exist in `src/core/3d/commands/` — grep their ids and arg schemas), Escape cancels.
4. Snapping, pivots, orientations: apply `snapPoint` during gizmo and modal moves; a header strip `SnapBar.tsx` (use the design-system components in `src/editor/components`, `ll:` prefix, tokens) with snap toggle + target, pivot and orientation dropdowns, bound to the store. The 3D cursor: command `3d.cursor.place` (Shift+right-click) uses `placeCursor`; new objects from `3d.add.*` appear at the cursor (read the cursor from the store when the command has no explicit location — add this as an additive default in a NEW file `src/editor/viewport3d/addAtCursor.ts` that wraps the add commands; do not edit the other command files).
5. View commands: register every `3d.view.*` command from B2-ids.md (front/back/left/right/top/bottom/toggle_ortho/frame_selected/frame_all/camera) and `3d.select.*` (all, none, invert, linked, similar, box) against the store, category "3D", with `when` true only while editing a scene. A view cube widget `ViewCube.tsx` (click a face for that view).
6. Document every UI choice in `DOCS/UI/DECISIONS.md` (append only; follow its format) and add demos of the new components to `/design-system` (grep `BudgetMeterDemo` for how).
7. Tests: unit tests for anything pure you add; an e2e spec `tests/e2e/viewport3d.spec.ts`: insert a scene, double-click to enter, orbit by dragging with the middle button, press `3d.view.top` via the command seam and check the store's camera view matrix, click the cube centre and see it selected, G X 2 Enter moves it exactly 2 m in X, Ctrl+Z undoes in one step.
