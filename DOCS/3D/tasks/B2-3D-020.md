# Task 3D-020 (keymaps) plus the pure data of 3D-018 (shading) and 3D-019 (overlays)
Read the "Phase 3D-018", "3D-019" and "3D-020" entries in DOCS/INITIAL/ROADMAP_3D.md and `DOCS/3D/tasks/B2-ids.md` (the canonical command ids). Pure TS, no DOM. Folders `src/core/3d/keymap/` and `src/core/3d/viewport/`.

`src/core/3d/keymap/`:
- `types.ts`: `KeyBinding {command: string, key: string, ctrl?, shift?, alt?, meta?, context: "global"|"object"|"edit"|"modal"}`; `Keymap {id: "blender"|"beginner", bindings: KeyBinding[]}`.
- `blender.ts`: the Blender keymap: G R S (modal transform), Tab (toggle edit mode), numpad 1/3/7 (front/right/top; Ctrl = back/left/bottom), numpad 5 toggle ortho, numpad . frame selected, Home frame all, numpad 0 camera view, Shift+A add menu, X and Delete delete, H hide, Alt+H unhide all, A select all, Alt+A none, Ctrl+I invert, L select linked, Shift+G select similar, B box select, Shift+D duplicate, P parent (Ctrl+P), Alt+P unparent, Z shading pie (letter keys for the four shadings are not bound; use numpad-free: Shift+Z toggles wireframe), Alt+Z x-ray, Shift+C reset cursor, Shift+right-click place cursor (command 3d.cursor.place, key "mouse2", shift), Ctrl+Space maximize is out of scope. Use the command ids from B2-ids.md only.
- `beginner.ts`: the editor's own keys: use simple unshifted keys (V move, R rotate, S scale is NOT allowed to collide with the editor's existing 2D keys: grep `src/editor` and `src/core/commands/globalCommands.ts` for keys already used and avoid them in the same context) and note which commands have toolbar buttons instead (`toolbarOnly: true` list for every 3D command without a key, so "beginners never need a key").
- `conflicts.ts`: `findConflicts(keymap)` returns pairs of bindings with the same key+modifiers in overlapping contexts (a `global` binding overlaps every context); `resolve(keymap, event, context)` returns the command id or null.
- Tests: no conflicts in either keymap; a scripted journey for each keymap (press sequence -> the list of command ids that would run: add cube, G X 2, Tab, frame, etc.); every binding's command id is in the canonical list; every canonical command is reachable in the beginner keymap (key or toolbarOnly).

`src/core/3d/viewport/`:
- `settings.ts`: `ShadingMode = "wireframe"|"solid"|"material"|"rendered"`, `ViewportSettings {shading, xray, overlays: {grid, axes, origins, faceOrientation, normals, wireOnShaded, stats}, solidOptions: {cavity, studioLight}, gizmoVisible}` with defaults, a pure reducer for the toggle commands, and zod schema + (de)serialisation.
- `stats.ts`: `sceneStats(doc, sceneId)` -> {objects, vertices, faces, triangles, estimatedMemoryBytes} computed from the data blocks (inline meshes and binary pointers).
- `shaders.ts`: GLSL strings (as TS constants) for the viewport's own shading: a Solid shader (studio lighting from 3 fixed lights + cavity-like darkening via a cheap curvature term), a wireframe-on-shaded shader (barycentric), a normal-visualisation shader, a face-orientation shader (blue front / red back), the selection outline shader (screen-space or inverted-hull). Pure strings with documented uniforms; a tiny `uniformsFor(mode, settings)` helper returning plain objects.
- Tests: reducer and serialisation round trip; stats on a known doc (cube = 8 vertices, 6 faces, 12 triangles); every shader string is non-empty, declares `#version 300 es` and the uniforms listed in its doc comment.
