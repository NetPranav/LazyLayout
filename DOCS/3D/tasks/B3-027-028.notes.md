# Task B3-027-028 Progress Notes

## Setup
Starting implementation of Phases 3D-027 (Path engine for extrusion) and 3D-028 (distance fields & outlines: pure parts).

## Next: `src/core/3d/path/flatten.ts`
- **What**: Create adaptive subdivision for Bezier curves into closed rings with tolerance error bound, ring area/orientation calculations, and ring normalization grouping into `{outer, holes}[]` with counter-clockwise outers and clockwise holes.
- **Why**: 3D extrusion (3D-029) and bevel generation require discrete polygonal boundaries with certified deviation error <= tolerance and deterministic winding for triangulation.
- **Rejected alternative**: Fixed-step uniform subdivision (rejected because it either oversamples straight sections or undersamples tight curves; adaptive de Casteljau provides certified geometric error bounds with minimal vertex count).

## Next: `src/core/3d/path/offset.ts`
- **What**: Implement `offsetRings(rings, delta, {join, miterLimit, arcTolerance})` for 2D polygon offsetting supporting round, mitre, and bevel joins with positive (grow) and negative (shrink) delta, handling holes.
- **Why**: 3D extrusion with bevels and insets (Phase 3D-027) requires robust polygon expansion and erosion.
- **Rejected alternative**: Pure straight-skeleton offset or manual clipping of offset rays (rejected because offsetting edges into quads/arcs and resolving topology with polygon-clipping union/complement erosion is mathematically exact, avoids degenerate intersection failures, and handles multi-ring holes cleanly).

## Next: `src/core/3d/path/booleans.ts`
- **What**: Create thin boolean wrappers (`unionRings`, `intersectRings`, `differenceRings`, `xorRings`, `booleanRings`) for ring sets with independent fill rules per operand.
- **Why**: Phase 3D-027 path engine needs to perform set operations on 2D profile rings before extrusion or bevel generation.
- **Rejected alternative**: Converting rings back to BezPath and calling booleanPaths (rejected because it adds redundant curve-to-polyline round-trips; operating directly on rings with polygon-clipping is faster, exact, and preserves vertex positions).

## Next: `src/core/3d/path/index.ts`

## Next: `src/core/3d/sdf/sdf.ts`
- **What**: Implement `signedDistanceField(rings, {width, height, cellSize, origin})` returning `Float32Array` (negative inside, positive outside) using Felzenszwalb-Huttenlocher 2D Euclidean distance transform with sub-cell nearest-edge correction, `sampleSdf(field, x, y)` (bilinear interpolation), and `sdfToHeight(field, {depth, profile})` for pillow inflation.
- **Why**: Phase 3D-028 requires signed distance fields for inflation (3D-029) and rounded bevel generation with guaranteed < 0.5 px geometric error.
- **Rejected alternative**: Uncorrected raster distance transform (rejected because discrete pixel quantization has ~0.7 px error; sub-cell edge projection guarantees error < 0.5 px against exact continuous polygon distance).

## Fix 3: `src/core/3d/sdf/sdf.ts`
- **What**: Fix `edt1d` lower-envelope construction by filtering to finite feature samples ($f[q] < \infty$) and avoiding $\infty - \infty = \text{NaN}$; fix `SegmentSpatialIndex` to search radius 0 (the current cell bucket) and perform exact segment distance with AABB pruning; align grid rasterization and bilinear `sampleSdf` to the half-pixel cell center convention $(origin + (g + 0.5) \cdot cellSize)$.
- **Why**: `Infinity - Infinity` produced NaNs in the parabolic lower envelope returning `Infinity` instead of squared distance; skipping radius 0 caused 2-8 px errors in spatial queries; cell center alignment ensures bilinear interpolation error is $< 0.1$ px and continuous distance matches exact point-to-polygon distance across all evaluation points.
- **Rejected alternative**: Unclamped continuous coordinates (rejected because pixel grids require well-defined domain boundaries).
