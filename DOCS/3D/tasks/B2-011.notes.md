# Task B2-011 Notes: 3D commands, undo & "Adjust last operation" (pure part + registration)

## Note 1: Architecture & Plan
- **What I am about to do:**
  Create `DOCS/3D/tasks/B2-011.notes.md` to track implementation for Phase 3D-011 (Task B2-011).
  Plan the modules:
  1. `src/core/3d/commands/primitives.ts`: Pure geometric mesh generators (cube, uvSphere, cylinder, cone, plane, torus, icosphere) returning `{ positions: Float32Array, indices: Uint32Array }` with outward-facing CCW winding, unit size defaults, and watertight closed topologies (each edge shared by exactly 2 triangles, signed volume > 0).
  2. `src/core/3d/commands/ops.ts`: Pure immutable functions `(doc: MotionDocument, args: unknown) => { doc: MotionDocument, selection?: string[], created?: string[] }` for all 29 canonical operations across Adding, Object, and Materials categories from `B2-ids.md`.
  3. `src/core/3d/commands/lastOperation.ts`: The "Adjust last operation" state manager that stores `{ id, args, docBefore }`, exposes `adjustLastOperation(newArgs)` to re-run the op and replace the undo step, `getLastOperation()`, `subscribe()`, `clearLastOperation()`, and `describeArgs(id)` for UI inspection.
  4. `src/core/3d/commands/register.ts`: Registers all 3D commands via `defineTypedCommand` into the global command registry, integrating with document editing and history undo/redo.
  5. `src/core/3d/commands/index.ts` & re-export in `src/core/3d/index.ts`.
  6. Additive registration call in `src/core/editing/editCommands.ts` alongside other command group registrations.
  7. Comprehensive test suite in `src/core/3d/commands/__tests__/commands3d.test.ts`.
- **Why:**
  Required for Phase 3D-011 of ROADMAP_3D. Delivers the core command pipeline for all 3D operations, Blender-style "Adjust last operation" parameter tweaking that updates the single undo step without stack pollution, and exposes all 3D commands to the agent/MCP interface with Zod schemas.
- **Alternatives rejected:**
  - Using Three.js geometry constructors directly: Rejected because Three.js geometries duplicate vertices across face seams and UV borders, breaking the manifold 2-shared-triangle watertight invariant needed for topological verification and boundary representation.
  - Recording a second undo step when adjusting operations: Rejected because in Blender and professional tools, adjusting the last added primitive's parameters (e.g. cylinder vertices from 32 to 64) must replace the original undo step so that hitting Ctrl+Z once returns cleanly to the state before the shape was created.

## Note 4: Adjust Last Operation Implementation
- **What I am about to do:**
  Create `src/core/3d/commands/lastOperation.ts` providing the "Adjust last operation" state management:
  - `recordLastOperation({ id, args, docBefore, title })`
  - `adjustLastOperation(newArgs)` which reverts to `docBefore`, re-executes the operation with merged arguments, and updates `useHistoryStore` by replacing the undo step in-place.
  - `getLastOperation()`, `subscribe()`, and `clearLastOperation()`.
  - Automatic invalidation on external document edits via `subscribeToDocumentChanges`.
  - `describeArgs(id)` introspecting Zod schemas into `{ name, type, default, min, max, step, options }` descriptors for UI rendering.
- **Why:**
  Required for Phase 3D-011 step 4. Enables Blender-style interactive primitive and modifier parameter tweaking immediately after creation without creating new undo steps.
- **Alternatives rejected:**
  - Pushing an undo step and immediately undoing it: Clutters history stack and risks desynchronization with autosave. Using `history.replaceLast` replaces the transaction in-place cleanly.
  - Hardcoded parameter metadata: Using Zod introspection via `describeArgs(id)` keeps schema definitions as the single source of truth for command arguments, UI panels, and agent schemas.
