# Tasks 3D-014 (navigation & views) and 3D-015 (selection in 3D): pure parts
Read the "Phase 3D-014" and "Phase 3D-015" entries in DOCS/INITIAL/ROADMAP_3D.md, and `DOCS/3D/tasks/B2-ids.md`. Y-up right-handed, metres (see `src/core/3d/units.ts`). Pure TS, no DOM.

3D-014, folder `src/core/3d/camera/`:
- `viewCamera.ts`: immutable `ViewCamera` {target Vec3, distance, yaw, pitch, fovY, ortho boolean, orthoSize, near, far}; `orbit(cam, dx, dy)` (pitch clamped just short of +-90deg), `pan(cam, dx, dy, viewportH)` (moves target in the view plane so the world moves with the cursor), `dolly(cam, delta)` (exponential, distance clamped), `zoomToPoint`, `flyStep(cam, {forward,right,up}, dt, speed)`, `viewMatrix(cam)`, `projectionMatrix(cam, aspect)`, `cameraPosition(cam)`.
- Standard views: `setStandardView(cam, "front"|"back"|"left"|"right"|"top"|"bottom")` with Blender numpad semantics converted to Y-up (front looks along -Z... pick glTF convention, document it), `toggleOrtho`, `frameBounds(cam, aabb, aspect)`, `frameAll`, `viewFromObjectCamera(cameraObject, doc)` (camera view).
- `gestures.ts`: pure mapping from pointer/touch input to navigation: mouse (middle=orbit, shift+middle=pan, ctrl+middle=dolly, wheel=dolly), trackpad (two-finger scroll=orbit with modifier rules, pinch=dolly), touch (one finger orbit, two-finger pan+pinch). Function `navigationFromGesture(event)` returning a nav delta.
- `tape.ts`: a navigation tape: array of steps {kind:"orbit"|"pan"|"dolly"|"view"|"frame"|"ortho", args}; `runTape(cam0, tape) => ViewCamera`. Test: a 15-step tape lands on exactly the expected view matrix (compute expected values by hand with the maths, not by calling the code under test; also test that orbit(+d) then orbit(-d) returns to the start within 1e-12).

3D-015, folder `src/core/3d/pick/` (may import `three` and `three-mesh-bvh`, which are installed):
- `ray.ts`: `rayFromScreen(x, y, viewportW, viewportH, viewMatrix, projMatrix) => {origin, dir}` (works for perspective and ortho).
- `bvh.ts`: cache of a three-mesh-bvh BVH per (meshId, version); `pickMesh(ray, {positions, indices, worldMatrix})` returning nearest hit {distance, point, faceIndex, normal}; `pickScene(ray, objects[])` sorted by distance. 100,000-face picking after the BVH is built must take under 1 ms per ray (assert < 3 ms averaged over 200 rays, log the real number).
- `select.ts`: pure reducer `Selection3d` {active: string|null, selected: string[]}: `click(sel, hitId|null, {shift,ctrl})`, `selectAll`, `selectNone`, `invert`; `boxSelect(objects, rect, viewProj, mode)` (object is selected when its projected bounds centre is inside; mode replace/add/subtract); `lassoSelect(objects, polygon, viewProj)` (point-in-polygon of projected origin); `selectLinked(sel, doc)` (same parent tree), `selectSimilar(sel, doc, by: "type"|"material"|"data")`; face-level `selectLinkedFaces(mesh, seedFace)` using shared-edge connectivity of triangle indices.
- `outline.ts`: `silhouetteEdges(positions, indices)` data for the outline pass (edges where one adjacent triangle faces the camera and the other does not is done in shader later; here just return the edge list with their two face normals).
Tests: exact picks on 30 generated test views (a known cube/sphere at known positions: the nearest-hit id and distance match analytic expectations within 1e-6); selection reducer cases; box/lasso cases; linked faces.
