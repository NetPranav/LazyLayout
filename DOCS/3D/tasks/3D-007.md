# Task 3D-007: 3D data blocks & schema v7
Read the "Phase 3D-007" entry in DOCS/INITIAL/ROADMAP_3D.md, `src/core/document/schema.ts` (SCHEMA_VERSION is 6), `src/core/document/migrations/` (follow v5-to-v6.ts and index.ts exactly), `src/core/document/factories.ts`, and the v7 row in DOCS/TEAM/CLAIMS.md.

Build:
1. Bump to schema v7, additive. New optional top-level tables on the document, each a record keyed by id: `scenes`, `objects`, `meshes`, `materials`, `lights`, `cameras`, `armatures`, `actions`, `worlds`, `images3d` (an image points at an asset-store id). Zod schemas for each data block in a new `src/core/document/scene3d.ts` (export types + schemas): Scene (objects ids, world id, activeCamera id, settings), Object (type, transform {location, rotationQuat, scale}, parent id, data id, material slots, visible), Mesh (positions/indices either inline arrays for small meshes OR a `binary: {assetId, vertexCount, faceCount}` pointer), Material (a plain PBR record: baseColor, metallic, roughness, emissive), Light, Camera, Armature (bones list), Action (fcurves list: target data path + keyframes), World. Unknown extra keys are rejected as in existing schemas.
2. A `scene3d` layer archetype (look at how existing archetypes like "frame"/"text" are registered in `src/core/document/registry.ts`) whose single property is `scene` = a scene id. Do not touch rendering.
3. Migration `v6-to-v7.ts` registered in `migrations/index.ts`: only sets schemaVersion 7 and leaves the tables absent (or empty); idempotent. All existing v6 fixtures must still load via migration.
4. Users rule: helpers in `src/core/document/dataBlocks.ts`: `userCount(doc, kind, id)` (how many objects/materials reference a block), `makeSingleUser(doc, objectId, slot)` which copies a shared material for that object only and returns the new doc (pure, immutable style like other document helpers), and `removeUnused(doc)`.
5. Large geometry: `src/core/document/meshBinary.ts` with `encodeMesh(mesh) -> {bytes: Uint8Array}` and `decodeMesh(bytes)` using a simple little-endian binary layout (magic, counts, Float32 positions, Uint32 indices). A 1,000,000-vertex mesh must encode in well under 1 s.
6. Tests: every block kind round-trips (parse -> serialise -> parse equal); v6 fixture migrates; bad data is rejected; makeSingleUser; mesh binary round-trip exact (incl. 1M vertices timing assertion < 1000 ms for encode+decode).
