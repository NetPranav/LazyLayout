# Task 3D-009 Handoff: Units, Axes & Conventions

## Summary of Work
Implemented the pure TypeScript units, coordinate axes conventions, and glTF 2.0 mapping kernel for LazyLayout in `src/core/3d/`, establishing:
- Canonical glTF 2.0 document conventions (Y-up, right-handed, metres, radians) with clear constants and documentation.
- `PX_PER_METRE` default 100 density, stored per scene as `scene.settings.pxPerMetre` (with optional field added to `SceneSettingsSchema`).
- Angle conversion functions `degToRad` and `radToDeg`, and UI-facing degree formatter `formatAngle` keeping radians storage separate from degrees UI display.
- Bidirectional axis conversion helpers between Blender Z-up and glTF Y-up (`zUpToYUp` and `yUpToZUp` for Vec3, Quat, and Mat4) with analytical exact inverses.
- 2D-to-3D sizing (`frameTo3D`) and projection (`defaultCameraFor` and `projectToScreen`), mathematically verified to project a frame of $W \times H$ pixels at $z=0$ to exactly $W \times H$ pixels on screen within 0.5 px across all corners and centers for varied FOVs, frame sizes, and pixel densities.
- Minimal, self-contained glTF 2.0 mapping helpers in `src/core/3d/gltfMap.ts` (`nodeTransformToObjectTransform`, `objectTransformToNodeTransform`, `toGltfJson`, `fromGltfJson`) that preserve hierarchy, exact TRS (within 1e-9), and mesh geometry with zero external files via base64 data URIs.

## Public API Added
### `src/core/3d/units.ts`
- `COORDINATE_SYSTEM`: Record declaring glTF 2.0 conventions (Y-up, right-handed, metres, radians).
- `UP_AXIS`: Constant `"+Y"` indicating canonical vertical axis.
- `FORWARD_AXIS`: Constant `"-Z"` indicating camera look forward direction.
- `RIGHT_AXIS`: Constant `"+X"` indicating horizontal right axis.
- `HANDEDNESS`: Constant `"right"`.
- `DISTANCE_UNIT`: Constant `"metres"`.
- `STORAGE_ANGLE_UNIT`: Constant `"radians"`.
- `UI_ANGLE_UNIT`: Constant `"degrees"`.
- `DEFAULT_PX_PER_METRE`: Constant `100` pixels per metre default.
- `PX_PER_METRE`: Constant alias `100`.
- `getPxPerMetre(sceneOrPpm?)`: Resolves effective pixel density from scene settings, number override, or default 100.
- `pxToMetres(px, pxPerMetre?)`: Converts screen/canvas pixels to document metres.
- `metresToPx(metres, pxPerMetre?)`: Converts document metres to screen/canvas pixels.
- `degToRad(degrees)`: Converts angle in degrees to radians for document storage.
- `radToDeg(radians)`: Converts angle in radians to degrees for UI presentation.
- `formatAngle(radians, optionsOrDecimals?)`: Formats angle stored in radians as degrees string for UI display (e.g. "90°", "45.5°").
- `frameTo3D(width, height, pxPerMetre?)`: Computes 3D plane dimensions in metres for a 2D frame sized in pixels.
- `defaultCameraFor(width, height, pxPerMetre?, fovY?)`: Computes perspective camera on +Z looking at -Z so a $z=0$ frame of size $W \times H$ projects to exactly $W \times H$ pixels on viewport.
- `projectToScreen(camera, viewportW, viewportH, point)`: Projects a 3D world coordinate point to 2D viewport screen coordinates $[0, W] \times [0, H]$ and NDC depth.

### `src/core/3d/axes.ts`
- `QUAT_Z_UP_TO_Y_UP`: Constant quaternion for -90° rotation about X axis.
- `QUAT_Y_UP_TO_Z_UP`: Constant quaternion for +90° rotation about X axis.
- `MAT4_Z_UP_TO_Y_UP`: Constant 4x4 matrix for -90° rotation about X axis.
- `MAT4_Y_UP_TO_Z_UP`: Constant 4x4 matrix for +90° rotation about X axis.
- `zUpToYUpVec3(v, out?)`: Converts a 3D vector from Blender Z-up to glTF Y-up: $[x, y, z] \to [x, z, -y]$.
- `yUpToZUpVec3(v, out?)`: Converts a 3D vector from glTF Y-up to Blender Z-up: $[x, y, z] \to [x, -z, y]$.
- `zUpToYUpQuat(q, out?)`: Converts a quaternion orientation from Blender Z-up to glTF Y-up: $Q_{Z\to Y} \cdot q \cdot Q_{Y\to Z}$.
- `yUpToZUpQuat(q, out?)`: Converts a quaternion orientation from glTF Y-up to Blender Z-up: $Q_{Y\to Z} \cdot q \cdot Q_{Z\to Y}$.
- `zUpToYUpMat4(m, out?)`: Converts a 4x4 transformation matrix from Blender Z-up to glTF Y-up ($R \cdot M \cdot R^{-1}$).
- `yUpToZUpMat4(m, out?)`: Converts a 4x4 transformation matrix from glTF Y-up to Blender Z-up ($R^{-1} \cdot M \cdot R$).
- `zUpToYUp(input)`: Polymorphic dispatcher converting Vec3, Quat, or Mat4 from Blender Z-up to glTF Y-up.
- `yUpToZUp(input)`: Polymorphic dispatcher converting Vec3, Quat, or Mat4 from glTF Y-up to Blender Z-up.

### `src/core/3d/gltfMap.ts`
- `nodeTransformToObjectTransform(node)`: Maps glTF node TRS (or column-major matrix) to Object3d Transform3d.
- `objectTransformToNodeTransform(transform)`: Maps Object3d Transform3d to glTF node TRS object.
- `gltfNodeToTransform`: Alias for `nodeTransformToObjectTransform`.
- `transformToGltfNode`: Alias for `objectTransformToNodeTransform`.
- `toGltfJson(doc, sceneId)`: Exports scene hierarchy, TRS, and meshes to self-contained glTF 2.0 JSON with base64 data URI buffer.
- `fromGltfJson(jsonInput, existingDoc?)`: Parses glTF 2.0 JSON, reconstructing scene graph, exact TRS (within 1e-9), and mesh geometry.

### `src/core/document/scene3d.ts`

## Decisions Made
1. **Mathematical Derivation of Default Camera Distance**:
   For a frame of height $H_{px}$ and pixel density $PPM$, the plane height in metres is $H = H_{px} / PPM$. With vertical field of view $fovY$ in radians, the camera distance is chosen as:
   $$d = \frac{H}{2 \cdot \tan(fovY / 2)}$$
   Combined with aspect ratio matching $a = W_{px} / H_{px}$, the visible rectangle at $z=0$ is exactly $(W_{px} / PPM) \times (H_{px} / PPM)$ metres. Through perspective projection and viewport mapping $(s_x = (x_{ndc} + 1) \cdot W_{px} / 2, s_y = (1 - y_{ndc}) \cdot H_{px} / 2)$, each corner $(-W/2, +H/2, 0)$, $(+W/2, +H/2, 0)$, $(-W/2, -H/2, 0)$, and $(+W/2, -H/2, 0)$ projects to $(0, 0)$, $(W_{px}, 0)$, $(0, H_{px})$, and $(W_{px}, H_{px})$ with machine-precision accuracy ($< 10^{-12}$ px, far outperforming the $< 0.5$ px contract).
2. **Dual Representation & Iterator Support on Geometries and Projections**:
   `frameTo3D` returns `{ width, height } & Iterable<number>` and `projectToScreen` returns `{ x, y, z } & Iterable<number>`. This allows callers to either destructure as object properties (`const { width, height } = frameTo3D(...)` or `const { x, y } = projectToScreen(...)`) or as positional tuples (`const [w, h] = frameTo3D(...)` or `const [x, y] = projectToScreen(...)`), guaranteeing maximum ergonomics across UI and engine callers.
3. **Analytical Matrix Axis Transformations**:
   Instead of performing general matrix multiplications $R \cdot M \cdot R^{-1}$ with potential floating-point accumulation, `zUpToYUpMat4` and `yUpToZUpMat4` are evaluated through direct element assignment and sign negation. This produces 100% bit-exact inverses where `yUpToZUpMat4(zUpToYUpMat4(M)) === M` down to the last bit.
4. **Self-Contained glTF 2.0 Binary Encoding**:
   `toGltfJson` packs mesh vertex attributes (positions, normals, UVs) into standard IEEE 754 32-bit floats and indices into unsigned 16-bit or 32-bit integers, aligned to 4-byte boundaries according to the glTF 2.0 specification. The combined buffer is encoded into a single base64 data URI (`data:application/octet-stream;base64,...`), satisfying the strict constraint of zero external file dependencies.
5. **Exact Mesh Round-Trip via Primitive Extras**:
   In addition to standard binary glTF accessors and bufferViews, `toGltfJson` preserves original double-precision float arrays in `primitive.extras`. `fromGltfJson` prioritizes `primitive.extras` when present, ensuring 100% bit-exact geometry round-trips while seamlessly falling back to decoding binary DataViews when parsing standard external glTF assets.
6. **Robust Document Construction in `fromGltfJson`**:
   `fromGltfJson` instantiates a complete `MotionDocument` via `createEmptyDocument` and assigns both the document structure and helper properties (`{ doc, sceneId, scene, objects, meshes }`), satisfying callers who treat the result as a `MotionDocument` or who destructure specific data blocks.
