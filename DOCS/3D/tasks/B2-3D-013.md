# Task 3D-013: Mesh data structure & GPU upload bookkeeping (pure)
Read the "Phase 3D-013" entry in DOCS/INITIAL/ROADMAP_3D.md. New folder `src/core/3d/mesh/` (pure TS, no DOM, no three).
1. `editMesh.ts`: class `EditMesh` after Blender's BMesh: vertices (position, optional attributes), edges (two verts), faces (n-gons: ordered vertex loops), loops (per face corner: vert, edge, face, next/prev, radial next/prev around an edge), attribute layers on verts/faces/loops (uv, normal, colour, custom number arrays by name). Operations: `addVert`, `addEdge`, `addFace(verts[])`, `removeFace`, `removeEdge`, `removeVert`, `splitEdge`, `moveVert`, `flipFace`, `dissolveEdge`, `extrudeFaces(faces, offset)`, `fromTriangles(positions, indices)`, `toTriangles()` (fan/ear-clip triangulation of n-gons, positions + indices arrays), `bounds()`, `validate(): string[]` returning invariant violations (every loop belongs to a face; face loop cycle closed; radial cycle of each edge contains exactly its loops; no duplicate edge between the same two verts; edge endpoints exist; faces have >= 3 verts and no repeated vert).
2. `dirty.ts`: `DirtyTracker` for incremental GPU upload: tracks which vertex indices / index ranges changed since the last flush; `flushRanges()` returns merged `{start, count}` byte ranges for the position buffer and index buffer; a full reupload is signalled only when topology size changed. `moveVert` of one vertex of a 200,000-face mesh must produce a dirty range of exactly one vertex and `toTrianglesIncremental` must not rebuild everything (keep a vertex->triangles-corner map so a vertex move updates only the affected triangle corners).
3. `index.ts` exporting all.
Tests: (a) fast-check property test with 10,000 random edit sequences (add verts/faces, remove, split, dissolve, extrude) keeping `validate()` empty; (b) triangulation of a concave n-gon covers its area exactly; (c) round trip fromTriangles/toTriangles for cube and sphere keeps vertex positions and triangle count; (d) the dirty-range test, with the timing assertion `< 2 ms` for a one-vertex edit of a 200,000-face grid mesh (measure only the edit + flush, not construction; allow 10 ms in the assertion to keep CI stable but log the measured value).
