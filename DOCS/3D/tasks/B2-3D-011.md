# Task 3D-011: 3D commands, undo & "Adjust last operation" (pure part + registration)
Read the "Phase 3D-011" entry in DOCS/INITIAL/ROADMAP_3D.md and `DOCS/3D/tasks/B2-ids.md`. Study how existing typed commands change the document and make undo steps: grep `defineTypedCommand` in `src/core/editing/editCommands.ts`, `src/core/frames/frameCommands.ts`, and `src/core/store/useHistoryStore.ts` / `useDocumentStore.ts`. Study how the agent bridge lists commands (`src/core/agent/agentHost.ts`; every registry command is exposed automatically, with its zod `args` schema).

Build in `src/core/3d/commands/` (new folder):
1. `primitives.ts`: pure mesh generators returning `{positions: Float32Array, indices: Uint32Array}` for cube, uvSphere(segments, rings), cylinder(vertices, depth, radius), cone, plane, torus, icosphere(subdivisions). Outward-facing counter-clockwise winding, unit size by default, closed meshes watertight (tests: each edge shared by exactly 2 triangles; volume > 0).
2. `ops.ts`: pure functions `(doc: MotionDocument, args) => {doc, selection?: string[], created?: string[]}` (immutable, no mutation of the input) for EVERY id in B2-ids.md under Adding, Object and Materials (skip Selection/View/Transform-modal/Mode/Shading/Overlay/Menu: UI phases do those). Use ids from `src/core/ids.ts` helpers, the 3D-007 data blocks, 3D-008 hierarchy/apply, `makeSingleUser`. Parameters via zod schemas (e.g. cylinder: `{vertices: 3..256 default 32, radius, depth, location?}`).
3. `register.ts`: `register3dCommands(): () => void` registering each op with `defineTypedCommand` (category "3D", title like "Add Cylinder", the args schema), executing through the same document-edit + undo-step path the other commands use, so ONE gesture = ONE undo step. Export it from `src/core/3d/commands/index.ts`. Also call it where the other command groups are registered (grep `registerAgentCommands(` to find the place) — additive only.
4. `lastOperation.ts`: the "Adjust last operation" model: after a command runs, `recordLastOperation({id, args, docBefore})`; `adjustLastOperation(newArgs)` reverts to `docBefore`, re-runs the op with the new args and REPLACES the undo step (still one step). Expose `getLastOperation()`, `subscribe()`, `clearLastOperation()`, and `describeArgs(id)` (field names, types, min/max from the zod schema) so a UI panel can render the controls. Any other edit clears it.
5. Tests: (a) every op: undo/redo round trip leaves the document deeply equal (30+ ops); (b) every registered 3d command has an args schema and a title; (c) the generators are watertight; (d) adjustLastOperation: add cylinder 32 -> set 64 gives a doc equal to adding 64 directly, and one undo returns to before; (e) the agent-visible list contains all ids.
