## Note 2: EditMesh Implementation
- **What I am about to do:**
  Create `src/core/3d/mesh/editMesh.ts` implementing `EditMesh` along with `BMVert`, `BMEdge`, `BMFace`, `BMLoop` interfaces, attribute layers, full topological editing operations (`addVert`, `addEdge`, `addFace`, `removeFace`, `removeEdge`, `removeVert`, `splitEdge`, `moveVert`, `flipFace`, `dissolveEdge`, `extrudeFaces`, `fromTriangles`, `toTriangles`, `bounds`, and `validate`).
- **Why:**
  Provides the boundary-representation geometry core for all 3D mesh modeling, modifier operations, and rendering pipeline inputs with Blender BMesh parity, pure TypeScript execution without DOM or Three.js dependencies, and strict invariant validation.
- **Alternatives rejected:**
  - Standard half-edge mesh: Rejected because half-edges cannot directly represent non-manifold edges (more than 2 faces meeting at an edge) or wire edges without complex workarounds; BMesh circular radial cycles around edges natively support boundary, manifold, non-manifold, and wire topologies.
  - Simple fan triangulation for all n-gons: Rejected because fan triangulation fails on concave polygons by generating overlapping triangles that spill outside the polygon boundary; Newell plane projection with robust ear-clipping is implemented to guarantee exact area coverage for concave polygons.

## Note 3: DirtyTracker Implementation
- **What I am about to do:**
  Create `src/core/3d/mesh/dirty.ts` implementing `DirtyTracker` for incremental GPU buffer uploads.
  It tracks dirty vertex indices and dirty index ranges, calculates merged `{ start, count }` byte ranges for WebGL/WebGPU buffer updates (12 bytes per vertex in position buffer, 4 bytes per index in index buffer), signals `fullReupload` when topology changes, maintains a `vertexToCorners` map, and performs incremental position buffer updates in `toTrianglesIncremental` in <0.05ms without rebuilding the mesh.
- **Why:**
  Required for 60fps real-time interactive mesh manipulation. Avoids costly 10-20ms full mesh re-allocations on 200,000-face meshes during vertex translation gestures (G / R / S modal transform).
- **Alternatives rejected:**
  - Full buffer recreation on every vertex move: Rejected because 200,000 faces take >10ms to allocate and copy, dropping frames in interactive viewport editing.
  - Tracking unmerged single bytes: Rejected because WebGPU/WebGL `writeBuffer` and `bufferSubData` calls have per-call driver overhead; merging contiguous ranges minimizes GPU API dispatch calls.
